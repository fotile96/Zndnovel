## 实弹事故记录

### E1 — id 9874 判死：`jp_tail` 未剥 `_n`（2026-08-07，ds-flash，session 2 / b50）

```
frozen jp   : 怒鳴り声。_nざわめき。_n悲鳴――
期望 jp_tail: わめき。悲鳴――        （剥掉 _n 后取末 8 字）
ds-flash 给 : き。_n悲鳴――          （把 _n 当成串里的普通字符一起数）
```

判死规则命中「`jp_tail` 与 frozen 重算的期望值不符」。**该行的 `zh` 与 opus 逐字相同**
（是一条零改动行），所以实际损失只是「9874 本轮拿不到 ds-flash 候选」——不触发覆盖不完整
（ingest 按「出现过即算覆盖」判定），fable-wf 一侧仍覆盖该 id。

**性质判定：零星失误，非系统性理解偏差。** 同一会话 487 行里仅此 1 行错，其余 486 行 `_n`
都剥对了；session 1 的 566 行零判死。若是理解偏差，含 `_n` 的行会成片判死。

**但它是 F2 那条留白的直接兑现**：契约没把「剥离控制码」的范围写死，模型就没有一个可以
稳定回退的机械规则，只能每行凭记忆执行——这类规则一旦不是字面可判定的，出错率就不是零。
段末复盘时 F2 应按「已产生生产损失」的优先级处理，把控制码剥离清单在契约里逐个列全
（至少 `_n` / `_r` / `<漢字,かな>` ruby 的取舍、半角与全角空格是否计数）。
