## 一、考题的答卷：四家维持，一家给出实质反方案

派发词里就 `5683`–`5685`（弥留意识的同音异字三连）向五通道征询更优解。结果值得逐条看。

### 原文的机制是"日文输入的两级失败"

```
5683  曲を きか ないと    ← 平假名：有音、字形还没定       ①未转换
5684  曲を 訊か ないと    ← 訊く＝询问：转换了，但选错词   ②选错（但成词）
5685  曲を 聴か ないと    ← 聴く＝聆听：终于对上           ③落定
```

### 三个候选方案

| | 三环 | 机制对位 | 音 | 字库风险 |
|---|---|---|---|---|
| **A 现行**（v13 起） | 汀 → 厅 → 听 | ①②**同质**——两环都是"不成词的错字"，`訊く` 那一环"成词但义偏"的机制没进中文 | 三字全 **tīng**，严格同音 | 零（全在常用简体字集） |
| **B glm-5.2 提案** | 厅 → **停** → 听 | ①②③**全对位**——厅＝常用字但绝不是动词（明显胡话）；停＝真动词、整句成立、义偏成"让曲子停下"；听＝落定 | 停是 **tíng**（二声），破严格同音；但 IME 敲 ting 时停/听同键近邻 | 零 |
| **C 存档待实测** | 听 → **聴** → 听 | `聴` 就是原文用的那个字形，等于把原作那一格原样搬来，异物感是"日式的"而非"繁体化" | 同音 | **高** |

**四家（ds-flash / fable-wf / glm-5.3 / opus46-wf）判维持 A**，理由互补：

- **ds-flash**：同音池已穷尽——普通话 tīng（阴平）常用字只有 听/厅/汀 三个，不存在第四选项。
- **glm-5.3**（分析最深）：指出 A 的**唯一结构损失**就是①②同质，并论证**不可修**——中文复刻"有音无形"的唯一载体是拼音，代价是视觉断裂＋带调字符的 PGF 不可测。它还纠正了派发词里我的一个假设：**原作要的不是"向正字逼近"的梯度，而是"错两次、第三次对"**。
- **fable-wf**：机制对位准——原文的失效点是假名→汉字的转换选字，中文的同构机制正是拼音输入法的同音选字错误；且三字零字库风险。
- **opus46-wf**：用不成词的字反而更贴"意识还没清醒到能组词"的状态，比用错义的实词更切合弥留。

**glm-5.2 独家提 B**，论证也扎实：现译前两环是同一种错，而原文三环是三种状态；`停` 居中环恰是 `訊く` 的位置——"自洽地偏成让曲子停下，与上文『得侧耳细听』相抵触，错可察觉、又到 5685 才坐实"。

### ⚠ 一个必须澄清的历史问题

四家都提到「`停` 曾被否过」。我查了手记，**实情比这更微妙**：

那句否决（"`停` 在此语境里能读成「必须让曲子停下」这个自洽的另一个意思，会失去「写错了」的信号"）
写在 `notes/e2s.md` 的**「闻／问／听」那一节里**，而那一节整体已于 2026-08-06 抽读 gate 被你否掉
（判「效果糟糕」），手记明确标注：

> 上方那一节**仅作决策过程备查，不得据以校对或润色**。

也就是说，那句话原本是为论证"选闻/问**而不选**停"而写的，**随那一版一起作废了**。
glm-5.2 具体断言的"那次是「停／问／听」三连、停在首环"我在手记里**查不到依据**（手记只写
"停/听 近音方案"，未标环位）——但它的实质论证不依赖这个断言。
**结论：`停` 从未被单独、正式地否决过。** B 是一个可以正经考虑的新提案，不是翻旧账。

### 我的倾向：维持 A，但这确实是价值判断

取舍点很清楚：**严格同音（A）vs 三态机制对位（B）**。我偏 A，两条理由：

1. **`停` 的自洽风险是真的，而且比 glm-5.2 估计的高。** 上文是 5676「远处传来了音乐」→5678「回家的歌谣，就是它」→5681「得侧耳细听才行」。在这个语境里，「得停那支曲子才行」读者第一遍**很可能当成情节**（她想让那催她"回去"的歌谣停下）——弥留场景里这完全讲得通。要等 5685 才回头发觉是错字，而"回头发觉"的读者比例存疑。A 的「汀」「厅」是当场就知道错了。
2. **①②同质是中文的固有缺口，不是 A 的失误。** 中文书写系统里没有"有音无形"这一态（拼音不是中文书写的一部分），glm-5.3 的论证我认同。为补一个本来就没有载体的机制而牺牲三字严格同音，不划算。

**若你倾向 B**，建议取 glm-5.2 的「厅→停→听」而非「汀→停→听」——它对「汀」的批评成立：生僻字会让读者怀疑"是不是我不认识的动词"，而「厅」是常用字、绝不是动词，作首环的"胡话"信号更干净。

**方案 C 仍在等字库实测**，与 CLAUDE.md 里 ruby 拼音注音那个待办（字库是否含带声调拉丁元音
`ā á ǎ à`）是同一类——都要在游戏内验证 `pgf/LXGWWenKai-Regular.pgf` 的字集覆盖。
**建议哪天做实测时两件事一起做。**
