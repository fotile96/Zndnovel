## 一、三条缺陷的修法

### 缺陷 1：`prewire_ids` 不认区间写法（阻断级）

- **先 grep 了真实语料确认分隔符**，没有照猜：`pilot/lanes/opus/data/notes/*.md` 里
  `id …` 上下文中实际只出现两种——半角连字号 `-`（6 处）与 en dash `–`（45 处），
  共 51 处；没有波浪号、没有全角减号。
- **但 50 处里绝大多数不在提案正文里**：36 处落在 `## batch NN（id 9231–9337，…）`
  这类批次标题行上，而 `cluster_notes.parse_notes` 对 `BATCH_RE` 匹配的行 `continue`，
  它们根本进不了 `proposal["body"]`。**真正影响审计的是提案正文里的 14 处**（crd 2 /
  s0f 1 / s1f 1 / s1s 3 / s2s 2 / sys 5）。这一条与交办描述的差异如实记在这里。
- 修法：`ID_RE` 字符类加入破折号全谱 `RANGE_DASHES = "-–—―‐‑‒−~〜～ー－ｰ"`（语料只用
  到两种，但手记是人手写的，漏一种就等于把整族承诺静默截成首个 id，故一次收全）；
  新增 `_TOKEN_RE` 以「单个 id 或一段区间」为单位 `finditer`，天然保序、且区间两端
  不会被当成两个孤立 id。
- **防区间爆炸（三重，全部留痕不静默丢弃）**：
  1. `PREWIRE_ID_LIMIT = 100`：单条提案展开后 id 总数上限，超限截断并在
     `notes` 里写明「保留前 N 个，另有 M 个未纳入（不是没抽到，是被上限挡下）」。
  2. `MAX_RANGE_SPAN = 10000`：单个区间跨度上限，`id 1–99999999` 这类笔误拒绝物化，
     只保留两端并留痕（语料实测最大跨度 72，离这条线很远）。
  3. 起止倒置（`id 200–100`）：照 `range(a,b+1)` 展开会得空集、把两个写明的 id 一起
     吞掉；保留两端并留痕。
- API：新增 `prewire_ids_detail(proposal, *, limit)` 返回
  `{"ids","notes","truncated","dropped"}`；`prewire_ids` 保留为只取 `ids` 的便捷形式，
  **既有调用与既有测试签名不变**。留痕经 `promise["prewire_note"]` 一路传到
  `render_report`，非空时印 `- ⚠ id 抽取留痕：…`。
- 语料回归：478 条提案全跑，抽出 id 总数 578，**无一条触发上限**（最大 crd b10 #2 = 72、
  s2s b60 #3 = 61、sys b5 #4 = 42），上限是安全网不是常态闸。

### 缺陷 2：`verify_promise` 不把提案正文传给模型

- 修法：user 消息新增 `【提案正文】` 段，位于 `【出处】` 与 `【相关行】` 之间；
  预拼路径与工具兜底路径**都传**（后者材料本来更少，更需要）。
- 截断：`PROPOSAL_BODY_LIMIT = 6000` 字符，`_clip_body` 超限时追加显式标记
  `［⚠ 提案正文过长已截断：原 N 字符，此处仅含前 6000 字符］`；结果 dict 新增
  `body_truncated`，`render_report` 对 True 印一行「判据若落在截断段，该条判定不可尽信」。
- `VERIFY_SYS` 同步改写：告知模型正文里可能藏着表格/清单式的判据，且截断时若判据
  落在截断段应判「无法判断」。
- 没有为省 token 只传摘要——按交办要求原样传。

### 缺陷 3：`evidence_ids` 与抽取阶段口径不一致

- 修法：`verify_promise` 改用 `_clean_model_ids`，与抽取阶段同一口径——纯数字字符串
  （`"7327"`、`"007"`）被接受并转 int，`bool`/浮点/非数字字符串丢弃并记入新字段
  `evidence_ids_invalid`，`render_report` 印「⚠ 模型给出的依据行含非法项已丢弃」。
- 非 list 的 `evidence_ids`（模型偶尔直接给标量）包成单元素 list 再清洗，不再整条丢掉。
- **口径修的是代码，不是那 3 条的因果**：sidecar 存的是过滤后的值，无法反证 v1 那 3 条
  「已履行 + 依据行（无）」当时收到的就是字符串。本报告不把它们说成已证实的因果。
  可观察到的事实：v2 的 14 条结果 `evidence_ids` **无一为空**（v1 有 3 条为空），
  但 v2 同时改了正文投喂，两个变量同时动过，不能归因到单一修法。

### 一处既有测试的断言口径调整（必须点名）

`test_verify_does_not_fall_back_to_prewire_ids_when_model_says_none` 原断言
`"5001" not in seen["user"]`。加入提案正文后该字面必然出现——正文里就写着
`- id 5001、5002`，而让模型读到正文正是缺陷 2 要修的东西。

我**没有删掉这条断言**，而是把它重定向到它真正要守的 invariant：不得拿 `prewire_ids`
去 `call_tool` 预取行、把结果当既定依据塞进【相关行】。新断言是
`call_tool` 零调用 + `【相关行】` 段仍是兜底占位符 + `"5001"` 不出现在该段内——
比原来的整串字面检查更贴题也更严。理由与取舍写在测试 docstring 里。

`tests/test_audit_seeded.py`（spec §5.1 硬门）**未改动、4 passed**。

## 四、crd b10 #2 的判定变化与**独立复算**

- v1：该提案抽出 6 条承诺，其中
  - 「本批伪说话人标签已按表内译法统一落笔」→ **无法判断**，理由原文：「…承诺所依据的
    『表内译法』表未随材料给出，且仅凭单行无法核对 19 个标签的『整族统一落笔』」——
    正是缺陷 1（只送进 1 行）+ 缺陷 2（表不传）双重造成的假不确定。
  - 「【≦＊＊＊≧】原样保留不译」→ **无法判断**（模型输出非法 JSON）。
- v2：该提案抽出 1 条合并承诺「伪说话人标签族译法已按表格定稿并落笔」→ **已履行**，
  依据行 18 个，理由点名 `【タイトルメニュー】→【标题菜单】` 等具体对应。
  `used_tools=否`——72 行全部由预拼送进，模型不必再检索。

**我的独立复算（不信模型，直接算数据）**：把提案表格的 20 行原文→译法对照写成 dict，
对 `get_lines(17050..17121)` 全部 72 行取行首 `【…】` 标签逐一比对：

```
带标签行数 ok: 72   违约: 0   未译: 0   表外标签: 0
```

抽查交办点名的 3 个 id（均**原样保留** `【≦＊＊＊≧】`）：

| id | 原文 | 译文 |
|---|---|---|
| 17051 | `【≦＊＊＊≧】本作を手にして頂き、ありがとうございます。` | `【≦＊＊＊≧】感谢您选择本作。` |
| 17118 | `【≦＊＊＊≧】以上でこの解説は終了です。` | `【≦＊＊＊≧】以上，本次说明到此结束。` |
| 17121 | `【≦＊＊＊≧】それでは、引き続きセカンドノベルをお楽しみください。…` | `【≦＊＊＊≧】那么，请继续享受第二物语。…` |

结论：**「已履行」经独立复算成立**，且比模型给的更强——模型只列了 18 个依据行，
实际是 72/72 全族无一偏离。

## 六、顾虑

1. **零「未履行」**：连续两次试跑、31 条承诺全无一条「未履行」。播种检验
   （`tests/test_audit_seeded.py`）证明工具**能**在人造违约上判出「未履行」，但真语料上
   的零命中还没有独立佐证。全量跑后应抽一条已履行的做反向复算（像我对 b10 #2 做的那样），
   确认不是「一律已履行」的顺从偏差。
2. **无法判断 0% 不等于可信度 100%**：该指标现在只反映「材料够不够」，不反映「判得对
   不对」。缺陷 2 修完后材料确实变足，指标随之归零是预期的；但这也意味着这个指标从此
   对「模型判错」不再敏感，需要另一条独立信号（例如随机抽样人工复核）。
3. **上限值未经真实压力检验**：`PREWIRE_ID_LIMIT=100` / `PROPOSAL_BODY_LIMIT=6000` 在
   当前语料上一次都没触发（最大 72 个 id / 正文远短于 6000 字符）。全量跑时若报告里出现
   ⚠ 留痕行，说明触到了新语料形态，届时应复核阈值是否合适而不是直接调大。
4. **生产会话仍在追加提案**：本次统计基于 2026-08-02 20:2x 的语料快照（478 条提案）。
   SEG-2 还在往 notes 追加，全量跑前的提案数会更大，外推需按届时实际条数重算。
5. **本次试跑的 44 次调用已计入 `data/api_ledger.jsonl`**（新增 44 行，行 108–151），
   未做任何回退。
