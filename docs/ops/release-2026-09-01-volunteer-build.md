## 怎么跑

- **模拟器**：PPSSPP 直接开 `game_zh.iso`。
- **实机**：CFW 的 ISO 加载器。盘是**就地替换**产出的——只换了 `DATA.BIN` 并平移尾部，
  其余字节与原盘逐字节相同（PVD、3 个目录区、DATA.BIN 数据区之外无差异）。这条路线是
  刻意选的：固件的 isofs 比 PPSSPP 严格得多，重建镜像会挑食。见
  `umd-iso-repack-research-2026-08-31.md`。
- ⚠ 盘比原版大 95MB（547 → 612MB）。`DATA.BIN` 原本是 LZSS 压缩存储，我们回封一律 raw
  ——`tools/databin.py` 的既定行为，不是这次引入的。UMD 容量 1.8GB，装得下。

## 发布闸

`build_disc.py --stage iso` 出盘前会跑 `check_release_clean()`，不过就拒绝出盘：

1. 封包树里不许有 `script/snr_test.lua`（测试引导的新成员）。
2. `build/stage/script/*.lua` 必须**逐字节等于**用同一个 luac 重编 `build/inject_src/*.lua`
   的结果——229 个全对。

第 2 条是关键：它不查特征串，而是拿译文管线的产物当基准整体比对。测试引导无论改了什么
（剥 IPL、改引导交接、短路某张卡的递卡），只要与管线产物不一致就会被抓住，不必逐个模式
去认，日后加新模式也不用回来改闸。

⚠ 闸查的是 `build/stage` 而不是 `build/inject`——两者会不同步，`--stage iso` 可以单独跑，
那时 stage 树是上一轮留下的。查真正被打进 `DATA.BIN` 的那一份才算数。

**这个闸是有由来的**：`inject_lua.py` 会清空明文源目录（`build/inject_src`）但**不清字节码
目录**，于是 `snr_test.lua` 会一直活着——它不属于译文管线的产物，没人覆盖它，也没人删它。
带着它出盘，志愿者一开机就直接掉进探针，而且看不出哪里不对，只会以为汉化版坏了。
