# `png/select/` 烤字清点（2026-08-08 初版；**2026-08-10 重大更正**）

> ## ⚠ 初版结论已被推翻，请先读这一节
>
> 初版（下文保留原样，作为错误记录）宣称：「141 个不同按钮里，**73 个的中文已经现成，
> 一条都不用补译**」。**这个结论是错的。**
>
> **错在哪**：初版用的推导链是「选项 → 分支值 → 目标场景 → 场景名」，并把场景名当作按钮上
> 的文字。但**推导给出的是「选完之后跳到哪个场景」，按钮上写的是「玩家选的那句话」**——
> 两者有时重合，有时不重合。
>
> **实证反例**（初版自己引为样例的那一条）：
>
> ```
> sel_s5s_350_sel_a  推导：ナースコールのボタン   图上实际：無理はしない        ✗
> sel_s5s_350_sel_b  推导：がんばってみる         图上实际：がんばってみる      ✓
> ```
>
> 「不勉强自己」导向的场景确实叫「呼叫铃的按钮」，语义相关，但**不是同一句话**。
>
> **量化**：2026-08-10 用**墨迹横向跨度核验**（按 16.59px/字标定，取自 6 组独立手工核对的
> 样本，落在 16.2–17.0px 的紧簇内）逐条比对推导结果与图上实测——
> **81 条「已解析」里 44 条吻合、37 条不吻合，错误率 46%**。四条不吻合已用逐像素读图独立确认。
>
> **这不是解析器 bug，是推导方法本身在结构上不可靠。**
>
> **教训**：初版把「推导链条成立」当成了「结论正确」，而**推导链的每一环都对，不等于链条的
> 前提成立**。初版只肉眼验了 1 条就写下「73/73 命中」——**一条样本不足以支撑一个全称结论**。
> 真正抓住它的是墨迹跨度核验：一个**独立于推导链的物证**。凡是靠推导得出的批量结论，
> 都该配一个不走同一条链的验证手段。
>
> **现状**：73 条「已有中文」中约半数需要重新确认；`select/` 的实际工作量**大于初版估计**。
> 详见 `.superpowers/sdd/2026-08-07-p4-polish-pass/select-survey-report.md`。
>
> 另有三处初版事实错误，一并更正：
> - `sel_voice1/2_sel_a_*`（480×82）**不是语音开关**，是序章高潮处的对白选择（已与 `vms()` 逐字核对）
> - `sel_map_1_a`（240×260）是此前未编目的**10 地点 × 2 状态的图标/标签表**
> - `sel_map_2_a`/`2_b` 是人物立绘，**不含文字**
> - `sel_map_off`/`on` 与 22 张 250×26 按钮是**零引用孤儿**（强证据但未 100% 证明是废弃素材，待裁）

## 一、资产形态

`png/select/` 共 **278 张**：

| 尺寸 | 张数 | 是什么 |
|---|---:|---|
| 250×26 | 268 | **选项按钮**，`_on`/`_off` 成对 → **134 个不同选项** |
| 480×82 | 4 | 待查 |
| 94×5 | 2 | 待查 |
| 480×42 / 240×260 / 180×92 / 240×84 | 各 1 | 待查 |

命名：`sel_<场景ID>_sel_<a..g>_<on|off>.png`，另有 `sel_map_*`（探索地图点）、
`sel_voice1/2_*`（语音开关）。去掉 `_on/_off` 后共 **141 个不同名**。

## 二、关键发现：选项文字可从 lua 机械推导，不必认图

**文字本身不在代码里**——`comDlgSelectItem` 只传图片名：

```lua
v49 = comDlgSelectItem(false, true, false, true, 1, "none", 0, 0,
        "sel_s1s_35_sel_a", 115, 80, 1,
        "sel_s1s_35_sel_b", 115, 120, 2,
        "sel_s1s_35_sel_c", 115, 160, 3)
```

**但分支去向能推出文字**。选项 → 分支值 → 目标场景 → 场景名，而场景名是有的：

```
sel_s1s_35_sel_a → 分支1 → s1s_37 → 「約束を思い出せない」
sel_s1s_35_sel_b → 分支2 → s1s_36 → 「約束をしている」
sel_s1s_35_sel_c → 分支3 → s1s_38 → 「約束をしていない」
```

三重互证：与 `CLAUDE.md` 记的「s1s_35_sel 三选（约束/想不起/没约）」逐条吻合；
与 `card_msg` 的 `『放課後の約束』の分岐（約束をしていない、している）` 吻合。

**分支有两种代码形态，都要处理**：

1. `if vN == k then doScriptScene = "场景ID"` → 再去查该场景的 `scene_X(doScriptScene, "标题")`；
2. `if vN == k then scene_XXX(doScriptScene, "标题")` → **标题就在分支块里**。

只认第一种会漏掉一大半（实测覆盖率从 34% 升到 51%）。

派生结果落在 `build/select_option_map.json`（可由分析脚本重跑）。

## 三、清点结果

| 类 | 数量 | 状态 |
|---|---:|---|
| ① 推出日文 **且中文已现成** | **73** | ✅ 直接复用 extra 轨的译文，**零补译** |
| ② 推出日文但缺中文 | **0** | — |
| ③ lua 引用但推不出日文 | 41 | 待处理，见下 |
| ④ 图存在但 lua 未解析到 | 27 | 待处理，见下 |

① 类实测 **73/73 命中**——`select/` 的按钮文字就是场景名语料本身。样例：

```
sel_s5s_350_sel_a  ナースコールのボタン → 呼叫铃的按钮
sel_s5s_350_sel_b  がんばってみる       → 试着撑一下
sel_s4s_30_sel_a   先生を受け入れる     → 接受老师
sel_s5s_80_sel_c   雪が降るって言うウワサ → 会下雪的传闻
```

### ③ 推不出日文的 41 个——按章分布

```
s2s 19 / s3s 10 / s6s 6 / s4fb 2 / s1s 1 / s4s 1 / voice1 1 / voice2 1
```

集中在 `s2s_190`、`s2s_192a/b/c`、`s3s_230`——**这些是 ナゾトキ（谜题）的多层选择迷宫**
（`CLAUDE.md`：「ナゾトキ 多层选择迷宫（答对/答错影响后续 s2s_260_sel 的选项集）」）。
谜题选项是**答案文本**，不是场景名，所以推不出。它们的日文可能只存在于图上。

`voice1/voice2` 是语音开关，属 UI，不是剧情选项。

### ④ 图有但 lua 未解析到的 27 个

```
sel_map, sel_map_0_a, sel_map_1_a, sel_map_2_a, sel_map_2_b   ← 探索地图点
sel_s2s_192b_sel_d/e, sel_s3s_230_sel_a..e, sel_s4s_210_sel_a/b, …
```

- **地图点名**：`comSelectMap` 走的是另一条调用路径，参数里没有明文名字。
  `CLAUDE.md` 记着地图点是「美術室/音楽室/保健室/職員室/中庭/校庭/教室/屋上/廊下/図書室」——
  **有已知清单，但与图的对应关系待定**。
- 其余多为谜题选项的延伸（`_d`/`_e` 档），与 ③ 同性质。

## 四、还需要做的

4. **版面测绘**：250×26 的按钮，文字是压在纯色底上还是压图？决定能否干净替换而不用色带
   （`plot/` 是压图，只能加色带）。**这一步没做之前，不要估工期。**
5. 那 10 张非 250×26 的异形图逐张查明用途。

## 五、方法论备忘

本面能省下大量工作，全靠一个判断：**先去代码里找文字，而不是先去图上认字**。
`plot/` 那轮同样是靠 `snr_common.lua:925-954` 的坐标算法确定格号映射，而不是靠像素猜。
后续 `card/`、`sysgim/` 开工前应先问同一个问题：**这批图的文字，代码里有没有？**
