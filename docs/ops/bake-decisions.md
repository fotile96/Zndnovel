# 烤字回填：已定裁决台账

> 每条都是**用户看过实物之后**做的决定。记在这里，是因为这些决定的理由多半来自
> 肉眼观感与取舍，事后从代码里读不出来——而代码只留下结果。
>
> 范围提醒：`.gim` 回转链路**本轮不做**（用户 2026-08-08 明示），所有面做到
> **正确的 PNG + 版面规格**为止。规格快照在 `docs/ops/bake-specs/`。

## `png/plot/`（4 张 × 60 格，82×48）

| # | 裁决 | 理由 |
|---|---|---|
| P1 | 日文字压在插图上、**干净底板不存在**（搜遍 `bg/`+`event/` 无匹配），故采用**逐格墨迹实测色带**遮盖，不用固定文字框 | 初版取中点那行逐列向上平铺，抹掉每格 48 行里的 28 行、58% 的插图。用户看图后否决 |
| P2 | 色带**逐行软硬分区**：压着墨迹的行强制不透明，从无墨迹的行保持真透明 | 实测单一均匀 alpha 做不到既盖住高对比白芯黑边字又保持透明感——alpha 250/255 时残留亮度 2–7% 仍能读出鬼影 |
| P3 | 卡 162（标题 logo 格，唯一墨迹检测回退格）：**只渲染「第二物语」，副标题 `〜彼女の夏、15分の記憶〜` 放弃覆盖**；色带按中文实际行数算（32 行→18 行） | 用户明示接受副标题部分可见。回退格「只按文字高度覆盖、日文可能残留」在 CLI/manifest/report 三处播报 |
| P4 | 折行按 `zh_wrap`，195 个卡名有 67 个断点变化 | 用户点名的卡 56「回荡在走廊的声音」：旧「…的声／音」→新「回荡在／走廊的声音」 |

## `png/scene/`（2 张 × 102 格，145×15）

| # | 裁决 | 理由 |
|---|---|---|
| S1 | 中文源是 **`skeleton/cards.zh.yaml` 的 195 条卡名**，不是 `scene_title` 数据集 | `snr_common.lua:955-984` 的 `sceneState` 循环 `for i8 = 1, 195` 按**卡号**索引，与 `plotState` 同一定义域；23/23 像素精确抽样交叉核对。那 454/393 条 `scene_title` 走 `savedataTitle()` 由引擎字体实时渲染，**从不烤进 PNG**。这一条推翻了立项时的错误前提 |
| S2 | 底色是**纯色 chrome 条**（RGB 恒 `(0,0,0)`，只 alpha 变化），故**不需要** `plot/` 那套逐格色带，固定 `TEXT_BOX` 即可 | 「先测底色形态再定方案」这条纪律的回报 |
| S3 | `__scene_1_a.png`/`__scene_2_a.png` 是**转换管线的孤儿**（RGBA 未量化版），引擎从不加载（`grep __scene lua_scripts/` 零命中），**原样不动、不烤** | 是否从仓库删除属仓库清理范畴，未处理 |
| S4 | **字号 11px 级联回落**：全局 11px，放不下逐格降到 10px（阶梯 `[11,10,9]`，通用多档）。用户看过 9/10/11 三版对照后选定 | 9px 是唯一零溢出值但偏小；10px 需把边距 5→3 才零溢出；11px 观感最好，代价是 4 条回落 |
| S5 | 回落 4 条，全部只降一档：卡 2、卡 90、卡 180、卡 182 | 回落在 CLI、`manifest.json`（含 `overflowed_at`）、`run()` 报告三处可见。**静默回落＝恒绿的一种形态** |

⚠ **S4 的已知代价**：11px 下 195 格全量实测最大墨迹高（含描边）**14px / 格高 15px**，
0 格越界，但最紧的卡 6「想不起约定」是**上边距 0px、下边距 1px 的不对称贴顶**。
**垂直余量已用尽**——此后译文若引入更高字形组合（带声调拼音注音、某些标点组合）可能切顶。
检查机制常驻在工具里（`manifest.json` 的 `vertical_clip_risks`），不是一次性的。

## `png/card/`（197 张，212×148；三块文字区：标题／左栏正文／右栏 section_label）

| # | 裁决 | 理由 |
|---|---|---|
| C1 | 右栏 `section_label` 的中文**单独存 `data/card_section_labels.jsonl`，不修订冻结骨架** | `cards.jp.yaml` 有 `section_label` 字段而 `cards.zh.yaml` 没有——右栏是卡面第三块文字，骨架里只有日文。20 种全由既有定译拼装（`セクション N`→`章节 N` 半角随骨架先例、`あらすじ`→梗概、`選択肢`→选项、`探索`/`日記` 同理）；`キーワード`→关键词、`物語あらすじ`→物语梗概、`物語？`→物语？ 三条为新造 |
| C2 | 正文重排规则：**整行是 `「…」` 形态的行，其前后都不与相邻行合并**；**卡 145 绘本体整卡不重排**；`\n\n` 段落边界（仅卡 41）保留 | 22 张「结构性换行」卡里 19 张是同一形态（选项各占一行 + 「有以上分支展开。」）。用规则而非逐张标记：**新卡进来机制自动认得，逐张清单会静默过期**。实测覆盖 quote-line 27 处 + 卡 145 自身 1 处 = 28/28。卡 145 的分行是童谣三顿节奏，**分行本身就是内容** |
| C3 | 字号：标题 11px／正文 9px／右栏 9px | 三块试排均零溢出。⚠ **正文 9px 最紧的行只余 2px**（卡 5/9/14/15 等），零溢出但零冗余——与 `scene/` S4 同类风险 |
| C4 | 背景**逐卡重建**（空白模板 `crd_0_d.png` + 各卡实测），不填单一颜色 | 底色是逐卡各自渲染的渐变，非纯色。**实测聚类结果是 2 类**：195 张常规卡（两两块距离 0.16–3.16，无间隙）+ 卡 94 独自一类（距离约 690，高三个数量级）。用户原估「几种到十几种」——**实测更集中，未为迎合估计硬拆**（强行切只会切在噪声上） |
| C5 | 重建验证闸：在原图确无文字处，重建背景与原图的 `max_diff ≤ 60` | 判据经两次失败迭代才定：①初版几乎到处误报（约 170 张）；②二版只剩卡 94 超阈（51，因色调不同）。终版判据＝「亮度 ≥235 **且** 在确认墨迹的 1px 膨胀之外」才算干净背景像素。实测 195 张 max_diff∈[15,34]，卡 94 约 52，0/196 超阈 |
| C6 | **卡 94 走显式白名单**：正文区跳过覆盖，标题与右栏照常渲染 | 卡 94 的正文区是**一幅人物插画**（肉眼确认），不是文字。若按 194 张的统一流程跑会整片抹掉。**用硬编码常量而非自动检测**——自动判据在「一旦错了就抹掉一幅画」的场合太危险。跳过在 CLI/manifest/report 三处播报，正文区经逐像素验证与原图完全相同 |
| C7 | 右栏三行标签（卡 26/118/158/162）的**非均匀行距 10px+25px 复刻成功** | 用户口径是「先尝试复刻，若有困难或效果不好就不强求」。实测 4/4 成功，回退到均匀行距的路径存在且有测试，但从未触发 |

⚠ **C5 的余量提示**：阈值 60 与实测上限 52 之间只隔 8。此后若卡面素材或字体变动使 `max_diff` 上移，
这道闸会先于观感失效之前报警——**这是它该有的行为**，别为了让它不响而抬阈值。

| # | 裁决 | 理由 |
