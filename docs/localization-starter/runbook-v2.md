# 游戏本地化执行手册 第二版草案

适用于原文脚本、主要控制脚本与美术资产可读的视觉小说和 2D RPG。目标是交付可运行、可通读、可修订的中文版本。执行顺序为：**可玩的中文切片与全作理解 → 编辑标准校准 → 代表性试点 → 逐场景完成翻译和验收 → 全作通读与发布。**

这份手册采用六项默认选择：实装尽早验证；上下文以场景证据组织；叙事约束与中文定稿分别管理；编辑工作台尽早投入；固定程序管理生产状态；新增模型和复审轮次以实际收益决定。角色和接口不绑定模型厂商。

配套的 [开工任务书](templates/v2/start-work.md)可直接交给执行 agent；[项目控制表](templates/v2/project-control.yaml)记录阶段与预算；[试点记录](templates/v2/pilot-record.md)用于决定何时扩到全量；[编辑判例](templates/v2/editorial-case.yaml)与[叙事约束示例](templates/v2/narrative-constraint.example.yaml)用于持续校准。这里定义的是执行合同，目标引擎的适配器仍需按实际项目接入。

## 默认配置和工作分工

从一个初译通道、一个独立复核通道和一位主编开始。通道指一套固定的模型、prompt、工具权限和输入方式；初译与复核可以用同一模型，但使用独立任务上下文。主编负责语言风格、歧义取舍和场景放行，不必逐条操作生产命令。

| 工作 | 默认承担者 | 交付与限制 |
|---|---|---|
| 提取、校验、版本核对、入库、恢复、构建 | 固定程序 | 结果带处理数量、输入版本与状态；不自行判断文学优劣 |
| 阅读原作、定位场景、解释疑点、请求取证 | 理解任务 | 事实、推测、未知分别记录，并给出处 |
| 中文初译 | 翻译任务 | 提交完整场景候选，不直接改现行译文 |
| 原文含义、演出、中文阅读检查 | 独立复核任务 | 交问题和修改建议，注明检查范围 |
| 品质标准、重要歧义、改判、场景放行 | 主编 | 留下可复用的判例和最终决定 |

这些是职责边界，不要求同时启动多个 agent。一个人和一个 agent 可以分时完成。多个任务共用数据时只保留一个正式写入口；能够确定性完成的步骤由执行器调用。

| 默认取舍 | 何时重新考虑 |
|---|---|
| 一个可运行场景通过后，再投入全量 | 暂无运行环境时仅做预算内的研究和试译，登记未验证项 |
| 一条初译加一条复核 | 新通道在盲评中持续带来独有真发现，且编辑成本可接受 |
| 以场景为阅读和放行单元 | 场景过长时分交付批，仍保留全场通读；不要截断对白回声或动作链 |
| 全作知识可查，当前分支单独标明 | 需要整章阅读时扩上下文；不把其他路线当作当前人物经历 |
| 语义修改经编辑放行 | 确定性模板派生可自动生成，但需唯一来源、结构和渲染校验 |
| 一轮初译、一轮复核、一次全作通读 | 抽查发现跨章节的同类缺陷，再决定定向召回或追加全文处理 |

## 阶段总表

阶段号描述进入全量生产的依赖。原作研究、测试与素材清点在后续阶段持续进行；第 5 阶段也随每个场景滚动执行。

| 阶段 | 交付 | 放行条件 | 未通过时 |
|---|---|---|---|
| 0 确认范围与基座 | 范围、原作指纹、启动条件、试点预算 | 版本和范围可追溯，首个片段已选定 | 补齐输入，或限定为研究模式 |
| 1 完成中文切片和全作初读 | 可玩切片、引擎合同、叙事地图 | 回写与运行正常，重要叙事依赖有出处 | 修适配器或补证，暂不扩产 |
| 2 校准编辑标准和场景包 | 通读面、判例、分层约束、输入合同 | 主编能连续阅读并作出可追溯修改 | 缩小界面，补代表性样本 |
| 3 跑代表性试点 | 固定条件的质量和成本记录 | 严重问题闭合，编辑负担可接受 | 根据根因改输入、工具或分工 |
| 4 逐场景生产 | 已复核文本、裁决、运行证据 | 每场结构、语义、阅读和运行检查完成 | 当前场景返回相应步骤，其他独立场景可继续 |
| 5 同步资产和召回 | 生效译文、关联素材与回归结果 | 受影响载体已更新，旧版本已标记失效 | 只暂停依赖这些内容的产物 |
| 6 全作验收与发布 | 通读结果、覆盖报告、发布候选 | 约定覆盖达标，阻断问题为零 | 定向修复；有系统性证据时扩大复审 |

## 阶段 0 确认范围与基座

先填项目控制表。必须知道：原作版本、目标语言、可用脚本与素材位置、能否运行、目标平台、编辑负责人、首轮可投入的试译量和人工时间。首轮预算可以按场景数、文本单元数或费用给出，不能全留空。

逐载体标记 include、exclude 或 deferred：正文、选择肢、姓名、UI、存档标题、数据库文本、图片字、影片字、语音独有内容、游戏内书籍及隐藏内容。排除项记原因，未知数量保持未知。原作新增内容、额外剧情和改编另列范围。

保存只读基座和文件指纹；翻译与逻辑适配写在旁路，所有回写先进入独立测试目录。对反编译脚本记录可靠性：哪些经过编译往返，哪些只有静态观察，哪些存在失真迹象。字节比较只规范化明确无关的元数据，不能借规范化消掉控制流差异。

选首个片段时兼顾正文、选择、图片字或动态串，以及保存后继续游戏。无法在一个片段内覆盖的功能，增加独立探针。不要为了选片段先做完整引擎模拟器。

**本阶段输出**：项目控制表、资产范围表、原始版本指纹、首个片段及验收清单。若缺运行条件，进入研究模式：继续清点、理解和预算内试译，记录待测项；取得运行环境后回到阶段 1 验证，才扩大投入。

## 阶段 1 同时建立运行证据和全作理解

### 中文运行切片

实现该片段的最小提取和回写，载入目标字体，生成一个测试版。逐项观察：文本显示、姓名和选择、控制码、变量替换、换行、等待、回看、跳过及存读档。对原作没有的功能标记不适用并说明原因。

至少做一次未替换译文的往返验证，以及一次含中文的运行验证。用原作正常游玩得到的入口证明路径可达；调试跳转或预置旗标用于局部复验，两类证据分别标记。正常存档和系统进度使用测试副本，记录所用原版与测试版。

把观察到的规则写成适配器合同：提取入口、回写定位、编码、占位符、标签和等待语义、字体与窗口限制、保存/载入限制、未知指令。每个结论附源位置或运行证据，不凭字符数猜像素宽度。

### 全作初读

按实际叙事结构完成全作初读，包括结局、路线分歧、图片里的剧情文字和已知特殊演出。允许分章阅读并汇总；未读部分明示。初读用于发现关系和机关，不要求此时把全作译成中文。

只维护足够支持后续工作的叙事地图：场景关系、人物别名与称呼、时间/叙事层、关键揭示、伏笔回收、必须保留的歧义。事实记录原文或资产出处，解释标为推测。全文很大时先做覆盖地图和高风险深读；某场景的关键依赖仍未读到，则暂缓该场景定稿。

特别检查文字与演出可能分离的地方：匿名说话人、异常语音对应、字幕和声音差异、指向动作、刻意重复、空白、画面中的提示，以及依赖选择历史的对白。

**放行条件**：中文切片可运行、可保存后继续；回写没有未解释的控制语义变化；范围内重要文本入口有登记；叙事地图能指回原作。错误属于适配器就先修代码，属于原作理解就补证，不用重译整批来碰运气。

## 阶段 2 建立编辑工作台和可更新的骨架

### 先让主编真正编辑几场戏

选择普通对白、情绪或文学段落、信息揭示、特殊口调等几类完整场景。给主编连续阅读的原译文和必要画面，记录采用、拒绝、改写与暂缓。特别保留被退回的模型润色建议及原因。

每条判例只写四件事：原来有什么问题，采用什么表达，依据是什么，适用到哪里。不同风格的章节出现时再补判例，避免拿日常对白规则约束全作。

编辑工作台的最小能力是：按场景读、看原文、打开证据、比较候选、保存草稿、提交裁决。可以先用本地静态页面加结构化裁决文件；无需先开发完整后台。界面显示当前译文版本，底本变化后提示复核，不能悄悄覆盖。

### 骨架中的事实与措辞分别管理

| 约束类型 | 约束内容 | 处理方法 |
|---|---|---|
| 逐字复现 | 密码、原句回收、规定的回声 | 登记关联 ID 和具体片段；中文定稿后统一绑定 |
| 概念一致 | 道具、身份、固定术语 | 登记概念、使用范围和允许变体，避免所有多义词一律同串 |
| 差异保护 | 不同层次称名、刻意异形、分支差异 | 说明差异必须存在的位置及叙事作用，禁止自动拉平 |
| 信息揭示 | 此处不得写出的实名、动机或结论 | 按路线、角色和揭示时点标记 |

所有约束再分 proposed、reviewed、binding。事实关系可以先成立，中文措辞仍为 provisional；不得用暂定译句覆盖新场景的其余内容。绑定译法重开时保留旧决定，并列出传播范围。

原作梗概卡可作为叙事证据；人工或模型摘要必须带来源。卡片/图片文字先完成内容稿，涉及全书反复出现的措辞稳定后再做批量美术定稿；技术样张在阶段 1 已经验证。

### 每个场景使用三类上下文

1. **全作知识**：关系、机关、时间与母题，供译者理解；不自动进入角色台词。
2. **当前证据**：原文上下文、路径条件、演出、说话人与受话对象、玩家及角色此时可知信息。
3. **编辑记忆**：相关定译、已裁判例、同族句与既有译文。

当前原文与证据具有取义依据的地位。既有译文与证据冲突时提出重开，不能为了前后一致延续误解。摘要不得把 inferred 改写成 observed，也不得把互斥路线合成同一过去。

通常按场景建立新上下文；连续场景可以共用会话，条件是路径和规则版本不变、输入记录完整、试点未发现明显漂移。新会话仍能靠持久材料恢复。全章阅读需要长上下文时使用长上下文，不为节省输入而拆坏叙事关系。

**放行条件**：主编能在工作台完成一场戏的修改；判例包含保留原稿和否决润色的情况；骨架能区分事实、解释、约束和暂定中文；关键判断可追溯。

## 最小数据合同

先采用结构化文件和单写者；有并发写入、查询或规模需求时再迁数据库。下面是逻辑记录，初期允许合并存放，保持身份和状态可追溯即可。现有 [模板目录](templates/README.md)提供基础示例。

| 记录 | 最小字段与不变量 |
|---|---|
| 原文 | `text_id`、源版本、原始串及 hash、文件/命令位置、文本类型、控制结构；不被译文覆盖 |
| 场景和出现 | `scene_id`、`occurrence_id`、路径/相关状态、原文 ID、前后关系、证据引用；同一文本可有多次出现 |
| 证据与解释 | 证据位置及 hash；claim 的 observed/inferred/unknown、适用路径与来源 |
| 叙事约束 | 约束类型、成员 ID/片段、作用域、状态、中文是否绑定、依据及旧决定引用 |
| 输入包 | 包 ID、实际输入文件及 hash、源/规则/译文版本、prompt 与通道配置、运行中追加材料记录 |
| 候选 | 文本 ID、源 hash、所见旧译 hash、候选版本、译文、待裁问题、输入包引用；备选只在必要时给 |
| 裁决和补丁 | keep/adopt/edit/defer、引用的候选版本、编辑者、最终文本及 hash、理由、被替代决定；校验绑定最终文本，陈旧底本不能入库 |
| 构建和覆盖 | 生效译文快照、素材/字体/工具版本、构建 hash、运行入口、观察范围、结果和未测项 |

`text_id` 与原文 hash 分开：位置决定身份，hash 检测该位置内容是否变化。原生 ID、标签或事件页索引也只在已登记的源版本中有效。原文升级采用身份映射，歧义单列；不要仅按相同字符串或行号自动重挂。

一个译文可能覆盖多个显示片段，引擎原生翻译单元也可能允许拆并。完整性检查以适配器登记的映射、可见内容和控制语义为准，不默认“输出 JSON 行数等于原作显示行数”。

同一文本位置在不同状态下确实需要不同中文时，先检查有无兼容表达；必要时登记条件译文，并由导出器实现选择条件。导出器不支持时保持待处理，不随机取其中一版。

## 阶段 3 用代表性试点决定生产方式

保留阶段 2 用于校准的样本，另选未用于写判例的验证样本。覆盖普通场景、深层前情、互斥分支、匿名身份、重复母题、动态串、图片选项和排版极值。可从几场完整戏、约 200–500 个单元起步；具体上限写入控制表，这个规模不承担统计学保证。

一次实验只回答一个主要问题，例如是否需要更多演出证据、哪条通道更适合初译、连续会话是否值得采用。固定源版本、规则、输入、权限和评价范围；不同方案的答案目录相互隔离。展示给主编时隐藏候选来源，保留单独的盲评映射。

| 指标 | 计数与判断 |
|---|---|
| 含义与知识边界 | 错误数/检查数，区分施受、指代、时相、提前揭示和无据补充 |
| 演出与中文阅读 | 被改平的重复/停顿/歧义，整场阅读结论；不只统计字面差异 |
| 结构与运行 | 漏项、错位、控制码、缺字、溢出、分支及存读档故障 |
| 发现与误改 | 复核的独有真发现、无效建议、引入的新问题，记录裁决依据 |
| 编辑与取证成本 | 按场景记录复核分钟数、请求补证的时间、调用成本；规模比较附单元数 |
| 未知 | 未运行检查、证据不足和样本未覆盖的类型 |

程序性校验用已知正确样本测误报，再用少量刻意损坏的样本测漏报。缺字段、零输入、规则未启用不能返回 pass。模型自评分只作线索，不用于自动授予免检权。

**进入全量前**：实际发现的严重问题已经修正并验证；主编认可场景阅读质量；生产能中断恢复；编辑耗时在事先约定预算内；未覆盖高风险类型已有明确取证任务。试点没覆盖的类型仍需在首次生产时专项检查。

若两种输入质量相当，采用更简单、总成本更低的一种。若差异只出现在个别困难场景，就给这些场景升级处理。增加通道先跑影子批；不因模型较新、窗口较大或自评分较高而直接扩全量。

## 阶段 4 每个场景的固定生产循环

### 步骤 1 准备输入并确认可译

执行器读取当前场景、相关原文与证据、绑定约束、判例和生效译文，生成不可变输入包。列出会改变取义的未知项，例如受话人、动态指代、未理解的插件效果。

未知项有指定补证动作：查某段脚本、听某个音频、回放某个入口或查看某张原图。能够保留原文歧义且不损失含义时允许先提出译法；关键事实未明的行不能标记已定稿。独立场景继续生产。

### 步骤 2 交初译候选

翻译任务连读场景后按稳定 ID 输出。默认一种译法；确有两可取义或编辑取舍时给有限备选及适用条件。普通行不强制写长批注；解释重点放在疑点、约束例外和可能引发召回的选择。

翻译任务可以检索原作和相关既有定译，但新增材料必须进入实际输入记录。若无法获得运行环境内完整的模型上下文，分别记录“可见的输入包与工具轨迹”和“不可观察的内部状态”，不把事后重建的包宣称为精确重放凭证。

### 步骤 3 封卷并做结构检查

候选先写临时文件，完成后封卷并登记内容 hash 和完成回执。进程 idle 或文件数量只能辅助确认，不能替代封卷。后续更改产生新 revision。

执行器校验原文映射、缺项/重复/错位、空值、placeholder、标签语法、控制语义与格式约束。可确定的机械修复由程序完成并留下变更记录；需要改变含义或语气的修复返回翻译任务。默认同类失败修复两次后诊断根因，停止重复整批派发。

### 步骤 4 独立复核含义并连续阅读中文

复核任务先看原文与证据，记录关键指代、动作关系、刻意歧义和疑问，再对照译文；默认不展示初译的自我辩护。对高风险句可先独立拟出理解或译法，降低顺着初译解释走的可能。

随后完整连读中文场景，检查节奏、口调、重复密度及信息落点。合理的另一种措辞不是必须修改的错误；原作的不规范、重复和停顿要结合演出判断。给主编的问题清单附原文、现译、候选、证据和改动范围。

### 步骤 5 编辑裁决和场景放行

主编优先处理含义冲突、演出差异、重开既有决定、改变叙事关系以及模型分歧；能影响多处的意见尽早形成判例。界面允许读完整场景，不能只提供拆散的候选卡片。

决定允许 keep、adopt、edit、defer。即使没有修改，也要有场景的检查范围与放行记录。未裁行保持待办，不因队列配额被丢掉。试点及新语域的首场由主编连续读完；常规场景按试点约定的复核范围执行。

### 步骤 6 唯一写入口接受当前版本

主编手改、采纳备选或合并候选后，对最终文本重新执行结构和排版检查；校验结果绑定这份最终文本的 hash。不能拿初始候选的通过记录替修改后的文本放行。未改动的候选可复用输入与规则版本都仍一致的校验结果。

执行器同时核对源 hash、所见旧译 hash、候选 revision、最终文本 hash、校验记录和裁决。缺一项或底本已改变就拒绝该次写入，重新对比后再裁。首次翻译使用明确的“尚无译文”基线，并核对当前位置确实未入线；首次接受写正向线，后续变化写补丁。下游只读 resolve 生成的生效译文。

单写者在锁内核对并提交；每次接受有唯一事务 ID，同一事务重试不重复落库。多文件记录用事务或可恢复的日志提交，不能把几次独立 append 当作整体成功。撤回已有修改也写新决定，保留审计历史。

### 步骤 7 构建并复看场景

从当前译文快照构建，用登记入口观察实际画面和声音，检查文字、选择、等待、相关资源及该场景涉及的存档行为。对白长度可能改变演出重叠，原文通过的场景仍需看译版。

正常路径证明可达，夹具入口检查局部表现。若一次构建包含多场景，可合并运行，但每场必须关联对应构建和证据。未运行时标记“语言已审，运行未验”，不能标记可发布。

### 步骤 8 记录断点并送入下一场

保存已接受事务、场景状态、未决问题、新判例、召回任务与下一步命令。持久状态决定恢复位置；聊天摘要只作提示。

候选路径为 `draft → sealed → validated → reviewed → decided → accepted`；defer 和 rejected 保留原记录。场景路径为“待输入 → 待译 → 待审 → 语言已审 → 运行已验 → 可发布”。源、规则或相关资产变化时，只使依赖它们的状态失效并安排重检。

## 阶段 5 滚动完成素材和召回

每个正文、按钮、图片字和攻略词条都引用明确的中文来源。图片亮暗/选中/虚化状态共用内容的，按原作事实派生；不能用下一分支标题猜选择按钮，也不能把 OCR 结果未经确认当原文。

素材条目保存源图、字框、文本来源、字体/字号/描边/补底配方、输出 hash 与原尺寸验收图。技术方案可以提前试样，批量烤字跟随已定稿内容。量化、缩放和纹理编码后的实际游戏显示仍要检查。

某项译法或叙事约束更改时，由依赖关系生成受影响列表：正文、同族句、图片、UI、攻略、字体字集、测试引文和截图。列表分为必须重生成、需要语境复核、不受影响并说明理由。无法穷尽依赖时增加定向搜索，保留覆盖边界。

先清楚表达改动意图，再逐处核对。原文同串可能不同义，中文同串也可能来自不同原文；任何一侧全文替换都不能代替语境判断。补丁落定后重建关联资产并复验，旧产物标记过期。

原作升级走专门的源迁移：保留旧版、建立身份映射、检查结构差异、处理冲突，再选择性重挂译文。不能把源版本迁移混成普通术语召回。

## RPG 的执行分支

RPG 在相同主流程中增加事件状态与运行轨迹，不另建一套译文数据库。

阶段 1 的切片至少包括一段会影响对白理解的走位或物件交接，以及一个不同条件下会改变对白的事件状态。先用几个手工证据包验证字段有用，再自动化采集。详细设计见 [RPG 工作流](rpg-workflow.md)。

| 加在何处 | RPG 必做工作 |
|---|---|
| 提取 | 保留地图/事件/页/命令、调用关系、条件、相关变量及公共事件；按具体版本实现语义 |
| 场景输入 | 提供模板原文与实际插值结果、角色位置/朝向/图像、地图与关键帧、玩家和角色知识 |
| 运行取证 | 分开记录命令下发与实际完成；并行事件、移动和等待保留时间关系 |
| 歧义处理 | 说话人、指代、物件、动态插件效果不能确认时请求最小补证 |
| 覆盖 | 按会影响语言理解的状态分组，记录哪些只是静态推导、哪些实际观察；插件不透明时不假定等价 |
| 译版验收 | 相同入口复看演出与对白的关系，验证实际发生的动作和相应措辞 |

三种输入按需升级：原文与附近对白；再加静态事件/相关状态；再加实际轨迹与音画。试点比较它们解决了哪些真实问题。走位和表情用于消歧，不直接改写成原文没有的心理描写。

可变数据库文本、任务前后 NPC 对话、队伍变化和战斗消息也进入范围表。只有实际影响译文的状态才扩上下文；无法排除影响的状态保留 unknown。自动探索和自主通关在取证需求足够明确后再立项。

## 阶段 6 全作通读和发布

在逐场景完成后进行一次全作连续通读，并对分支分别检查。重点找局部复核难以发现的问题：角色跨章节变化、重复词密度、长距离伏笔、叙事层切换、整体节奏以及跨载体名称。

发布检查分开统计：提取覆盖、语义复核覆盖、图片/音频覆盖、正常路线覆盖、状态类覆盖与平台覆盖。分母不能只来自同一个提取器；用独立字符串扫描、原生导出、运行记录和资产清点交叉寻找账本外遗漏。

不依赖模型给出统一“品质分”。阻断问题包括漏译/错位、已知实义错误、提前泄露关键身份、控制逻辑或存读档破坏、关键文字不可读。文字偏好和范围外内容由主编按项目标准登记，不用无休止改写追求零建议。

发布候选固定基座、译文、素材、字体、适配器和构建版本，确认测试跳转/解锁未混入。对目标平台执行约定矩阵，附已知问题和未覆盖范围。发布后反馈按场景和根因回流；同类错误跨场景反复出现时，再扩大抽查或重做相应类别。

**完成条件**：范围内条目均有明确去向，约定检查完成，阻断问题为零，主编接受整作阅读结果，可从登记输入重建发布候选。发布到外部渠道按项目既定授权另行执行。

## 异常和恢复速查

| 发现 | 立即处理 | 恢复依据 |
|---|---|---|
| 账本漏入口 | 暂停依赖该提取规则的覆盖结论，修提取并补独立扫描 | 新旧集合差异和漏项回填 |
| 候选仍在写或 hash 不符 | 不入库；要求新封卷版本 | 完成回执和对应内容 hash |
| 旧译在裁决后变化 | 拒绝陈旧写入，展示差异重裁 | 最新底本和新决定 |
| 规则互相冲突 | 标出冲突作用域，主编裁定；其他场景继续 | 明确取代关系的规则版本 |
| 同类校验连续失败 | 检查 schema、输入和适配器；停止重复整批重译 | 根因修复后的定点验证 |
| 模型声称已读/已查但无证据 | 检查可见轨迹和产物，缺失项标 unknown | 文件、运行记录及可验证结果 |
| 上下文遗漏导致误译 | 补相关原文/事件证据，只重做受影响场景 | 修订输入包与独立复核 |
| 演出解释发生争议 | 分离事实和解释，补音画或状态证据 | 主编裁定或保留歧义 |
| 工具升级 | 在场景边界固定版本，用好/坏样本检查预期差异 | 成对结果；未执行项不算通过 |
| 会话中断 | 从已接受事务、封卷包和检查记录恢复 | 不重放已成功的写操作 |

## 第一次开工照此执行

1. 填项目控制表，确认实际输入与首轮预算。
2. 建原作只读基座，选择首个场景，记录正常入口和待测功能。
3. 交替推进中文运行切片与全作叙事初读；先交可运行片段和有出处的理解地图。
4. 用简单通读面让主编改几个完整场景，形成判例与分层约束。
5. 在未用于写判例的场景上跑试点，交质量、未知项、取证和编辑成本记录。
6. 试点放行后，按阶段 4 的固定循环扩到全量，阶段 5 随场景滚动执行。

开工 agent 可以直接使用 [任务书](templates/v2/start-work.md)。既有承诺、术语定稿、原作素材和游戏逻辑只在明确的变更范围内修改；日常工具修复、数据核对与文档维护按授权继续推进。
