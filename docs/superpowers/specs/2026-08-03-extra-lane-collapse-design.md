# extra 车道（seg8，165 批 829 行）生产坍缩设计

> 定稿 2026-08-03，经 `/adhd` 发散（5 视角 30 点子）+ 3 路深化 + 逐节确认后落档。
> 上游：`config/segments.yaml` 的 `seg8-extra`（批次 174–338）。
> 动机：为未来 fable 车道全量生产省预算。

---

## 0. 目标与非目标

**目标**：把 extra 车道 165 批 829 行 UI/标题类短文本的生产，从「每批一次完整 subagent 会话」坍缩为「三层机械派生 + 3 组真实翻译会话」，且**对既有工装与流程的影响面最小**。

**非目标**（明确排除）：

- ✗ 修改 `data/batches.jsonl`（已冻结，opus 车道已按现划分在跑）
- ✗ 让下游校验链（canary / `check_batch` / `detect_collapse` / 手记审计）感知到坍缩的存在
- ✗ 把 opus 车道已产出的译文直接拷进 fable 车道充作其结果（摧毁双车道对照的意义，且违反如实记账纪律）
- ✗ 伪装调用次数（「一次大调用切片成 165 份、伪装成 165 次批次完成」属作弊，明确排除）
- ✗ 把本方案推广到 main 车道的正文批（正文批的上下文是累积前缀，性质不同）

### 1.1 连接键验证（歧义必须为 0）

骨架 `skeleton/cards.jp.yaml`（197 条）与 `cards.zh.yaml`（196 条）按 **`(card, variant)`** 连接，得 196 对。

> **方法论留痕**：首次验证误用 `zip()` 按行序配对，得出「`探索：放課後の学校` → {放学后的钱仙, 选择：ユウイチ的身影}」这类明显错误的「歧义」。**验证工具本身也会骗人，且骗人的方式恰恰是给出看起来很有信息量的结果。** 改用 `(card, variant)` 连接后歧义归零。任何后续复算须沿用键连接，不得按行序。

- **同一 `title_jp` 对应多个 `title_zh` 的：0 条**
- `plot_title` 195 行：**195/195 唯一命中**，0 歧义，0 未命中
- `card_msg` 匹配模板的 159 行中：**147 行连接命中**，12 未命中，**0 歧义**

未连接上的那条 jp 卡是 `card 0 / variant d`：**空白卡面**（无标题无正文，`png/card/` 中不存在该文件），骨架仅作版式记录。**无中文对应是正确的，不是遗漏。**

### 1.2 模板骨架验证（逐字节，非抽查）

`card_msg` 172 行中 159 行匹配 `^『(.+?)』の(あらすじ|選択肢（(.+?)）)を作成しました。$`。

对全部 159 行剥离可变子串、重建骨架、再往返填回并与原文逐字节比对：

- **往返重建不一致：0 行**
- **骨架种类：2 种** —— `『{NAME}』のあらすじを作成しました。`（133 行）、`『{NAME}』の選択肢（{OPT}）を作成しました。`（26 行）

### 1.3 场景标题重合与语境范围

- 454 行去重后 **393 个唯一值**
- 其中 **155 个与冻结卡名字面重合**，覆盖 **169 处出现**
- 真正需要翻译的唯一场景标题：**238 个**
- **374 个唯一标题只在单一脚本文件中出现**（无跨语境风险）
- **仅 19 个跨脚本文件出现**（`ゲームオーバー` 6 文件、`プール` 3、`オープニング` 3、`セカンドノベル` 2、`プラネタリウム` 2、`中庭の雪` 2 等）

## 2. 架构：批号与执行解耦

核心命题：**批号是交付/记账凭证，不是执行单元。**

- `data/batches.jsonl` **一字不改**，165 个批号骨架完整保留
- 生产按「产出机制」分层执行，与批号无关
- 产出**按原始 165 批的行数与顺序回填**
- 下游校验链只看得见展开后的原始形状，**永不知道坍缩发生过**

### 2.1 分层与分账

| 层 | 机制 | 覆盖行数 | LLM 调用 |
|---|---|---|---|
| **L1** 冻结代入 | `plot_title` 195 + `scene_title` 与卡名重合的 169 处 | **364** | 0 |
| **L1b** 规则代入 | 12 个 `セクションＮ` 章节名 + 绘本标题（见 §3.2） | **12** | 0 |
| **L2** 模板套壳 | `card_msg` 匹配模板且连接命中 | **147** | 0 |
| **L3** 真实翻译 | 场景标题残余 285 处（去重后 **238 个唯一**）+ 非模板 `card_msg` 13 + `savedata` 8 | 306 行 → **259 个唯一单元** | 3 组会话 |

**合计 523 行零 LLM（63%）**；LLM 工作量从 165 次会话降为 **3 组**。

### 2.2 provenance：逐行可追责

每行落盘时带三元组 `{mechanism, source_table, source_key}`，`mechanism ∈ {frozen_substitution, rule_substitution, template_fill, llm_translated}`。

**标签必须可反驳**：校验时刻由验证器**从原始输入重新推导**一遍「这行本该是什么 mechanism」，与落盘值比对，不一致即报警。

> 这一条针对深化阶段识别出的真风险：若 provenance 由坍缩脚本自己盖章、下游只读不验，标签就从「凭证」退化为**「新的一层需要被信任但不再被检查的自证」**——正是本项目已栽过六次的「恒绿的安全闸」的第七种形态。

## 3. 各层细则

### 3.1 L1 冻结代入

数据源：`skeleton/cards.jp.yaml` → `cards.zh.yaml`，按 `(card, variant)` 连接后取 `title_jp → title_zh`。

**准入条件：唯一命中。** 歧义（同 `title_jp` 对多个 `title_zh`）或未命中的行**一律不得自动代入**，退回 L3 并显式登记。

### 3.2 L1b 规则代入（12 行）

这 12 行是**成系统的类别**，不是零散残余，已有既定规则：

- `セクション１`…`セクションＥＸ１`：`glossary/style.md` v2 起 `セクション→章节`，格式「章节 1：アヤノ」
- `いつか きみが みる お話`：定译『总有一天你会看到的故事。』

**陷阱（必须逐条确认，不得字符串包含匹配）**：ledger 中该绘本标题**无句末 `。`**，而定译带 `。`。此类「字面不完全一致的定译」须逐条登记映射，自动代入只允许在字面完全一致时发生。

### 3.3 L2 模板套壳

用 §1.2 已验证的 2 种骨架，`{NAME}` 由 L1 已得的中文卡名填入，`{OPT}` 同理走卡名表。中文模板措辞在实现时定稿一次，登记为不可变映射表的一部分。

### 3.4 L3 真实翻译（**由 opus 跑**，用户裁决 2026-08-03）

分 **3 组**，理由是三类的判据不同，混跑会让各自的约束互相稀释：

1. 场景标题 238 个唯一
2. `card_msg` 残余 13 个（非模板形态）
3. `savedata` 8 个

**上下文形态是本方案真正的省钱来源**——不给累积剧情前缀，改为**常量参考包**：

- 该标题所属章别与层（`_s` 故事层 / `_f` 现实层）→ 决定人名用片假名还是汉字（双层人名规则）
- 冻结卡组中的近邻卡名 → 保持命名风格一致
- `glossary/active.json` + `style.md` 的 UI 词条款

该参考包**固定且不随进度增长**，与正文批的累积前缀性质不同。

**去重广播为独立命名阶段**：238 个唯一标题翻译完后，按字面相等广播回 285 处出现，此步骤须**显式落表**而非在回填时作为副作用发生——否则日后无法复算「`ゲームオーバー` 在 6 个文件里是否都拿到同一个中文」。

## 4. 验收装置

| 闸 | 判据 | 失败处置 |
|---|---|---|
| 连接键闸 | 同 `title_jp` 对应多个 `title_zh` 的数量 == 0 | 硬停 |
| 模板骨架闸 | 剥离可变子串后的骨架种类 == 2 | 硬停 |
| **往返幂等闸** | collapse → expand 后与原始 829 行**逐字节相等** | 硬停 |
| provenance 重算闸 | 验证器独立重推的 mechanism == 落盘值 | 报警并列出不一致行 |
| 语境闸 | 19 个跨文件标题逐条人工确认「可合并」或「按出现位置分治」 | 未确认者不得合并 |
| 下游无感 | canary / `check_batch` 输入为展开后的原始形状 | 结构保证 |

### 4.1 往返幂等是通用契约

**任何声称省钱的机械派生步骤，必须同时提交反函数，并在测试中跑一次往返幂等检查。** 这不限于本次 829 行——它是本项目此后对所有坍缩层的要求，防止下一次批次优化重新发明一个没有反函数的坍缩。

### 4.2 三张映射表享受不可变纪律

卡名代入表、模板还原表、场景标题去重表，比照 `batches.jsonl`：**有版本号、只增不改、变更单独留痕**。理由与 `glossary/*.yaml` 的 append-only 惯例同源——翻译决定必须可修订，但不得抹去「此前相信过什么」的记录。

## 5. 已签字的取舍：双车道对称性

**本方案增加 opus 与 fable 两条车道在 extra 段的不对称性。**

opus 车道按 165 批老实跑；fable 若走坍缩，两者在 extra 段不再是「同一流程的两次独立执行」。双车道存在的意义是**独立产出可比较**，坍缩后：

- L1/L1b/L2 覆盖的 523 行，两条车道**结果必然完全相同**（同一张冻结表的机械代入），比较失去意义
- 真正仍可比较的只剩 L3 的 259 个唯一单元

**判定（2026-08-03，用户）**：接受。L1/L2 本就是机械代入，两条车道跑出不同结果反而是 bug。

**此条显式入档，避免日后成为「为什么 extra 段的车道对照没意义了」的悬案。**

## 7. 边界（本 spec 不覆盖）

- main 车道正文批的分批策略（性质不同，上下文是累积前缀）——但见 §7.1 的实测留档
- `select/` 278 张、`plot/`·`scene/` 缩略图集等图片烤字的同类坍缩（结构相似，可复用本方案的 golden-diff 模式，但属图片轨）

- 润色任务的验收装置（另一条线）

### 7.1 留档：main 车道（seg1–7）的实测优化空间

本 spec 定稿前顺带量过 main 车道，**结论是本方案不适用**，但实测数据值得留档，免得日后重问。

**① 机械派生不成立**：正文没有可代入的冻结表，L1/L2 无对应物。

**② 小批合并收益 1%**：main 车道 173 批中 38 批 < 500 jp 字符（22% 的批次），合计仅 5007 字符 = 正文的 **1%**；且切点全是 `chapter`(24)/`branch`(14) 语义边界。收益与风险不成比例。

**③ 每批固定开销的实测构成**（`pilot/lanes/opus/work/ctx/batch_N/context.md`）：

| 节 | 体积 | 性质 |
|---|---|---|
| 一、冻结骨架 | 8442 字符 | 恒定 |
| 二、前缀正文 | 18K–50K | 随进度增长 |
| 三/四、术语+风格+7 份口调表 | **33K–36K** | 近乎恒定 |
| 五、本批任务 | 41–1810 | — |

**术语/风格/口调块每批 34K 字符、恒定不变，在部分批次比前缀正文还大。** 173 批即约 5.9MB 的重复投递。

已跑 95 批实测：context 合计 **18.5MB**，换来待译 **219KB**，整体开销比 **≈86x**；batch 3 以 137KB 上下文换 **9 个字符**（15557x）。

**④ prompt caching 目前被结构性堵死**（两层原因）：

- 相邻批 `context.md` 公共前缀仅 **6 个字符**——因为首行是 `# 批次 N（profile=cc）`，**批号写在文件开头**，前缀立刻分叉。**把批号挪到文末是一行改动，公共前缀立刻从 6 涨到几万。**
- 即便修好上一条，前缀也只稳定 42–62%：前缀正文**不是追加式**（b94→b95 公共前缀 55%，b94 尾部 38849 字符未被 b95 沿用），因为 compact 机制会把已做卡场景替换为卡面梗概、时间轴顺序会在中间插入。

**⑤ 骨架不是逐字冻结**：b46 与 b95 的骨架节长度相同但差一行——`【卡41】…原作→赝品` vs `→假货`，即 glossary v8 双层词裁定（`贋作`→赝品 / `ニセモノ`→假货）回灌进骨架渲染。行为正确，但**任何缓存都会在 glossary 版本跳变时整体失效**。

**变现前提**：④ 的收益在「每批一个全新 subagent 会话」的执行模型下**无法变现**（跨批没有共享对话前缀）。它只在两种情况下值钱：走 API 流水线（DeepSeek 已实测缓存命中良好），或改用单条长对话跑多批。后者另行评估。
