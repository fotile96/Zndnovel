# 新 VN 本地化项目 runbook

本篇保留第一版通用流程。新项目默认按 [第二版执行手册](runbook-v2.md)推进，其中进一步明确了早期编辑校准、叙事约束分层、实际输入留痕和逐场景放行。

适用前提：原文、控制脚本和主要图像可读；能运行原作或拿到可信游玩记录。不要求 Lua，不要求全书存在唯一线性路线。下文是推荐的新流程，不是声称本仓库已经实现的通用框架。

## 0. 最小配置与退出标准

先设一条初译通道、一条独立复核通道、一位最终编辑。角色可以由同一人/系统分时承担，但初译自检不冒充独立复核。保留结构化文件、版本控制、机械校验、一个简单的场景通读面；暂不要求五模型、向量数据库、自动全通关或多轮全书重译。

完成的定义：范围内可见文本有去向；批准的译文能构建；关键路径真实可达；控制符、选择逻辑和存读档正常；文本在实际窗口可读；高风险歧义已裁决；未覆盖项和保留日文有明确登记。

| 步骤 | 必须产出 | 何时通过 |
|---|---|---|
| A 盘点与基座 | scope、引擎版本、源码/资产指纹、启动记录 | 范围可数、可复原 |
| B 中文切片 | 最小提取/回写、中文字体、1 个场景运行记录 | 改得进去、跑得通、可存读 |
| C 文本/叙事建模 | 原文账本、场景/分支图、资源映射、未知项 | 可追溯、提取覆盖可独立检查 |
| D 骨架与试点 | 术语、口调、知识约束、代表样本、评价报告 | 流程可断续，问题可归因 |
| E 分段生产 | 冻结上下文、初译、校验、问题、入库回执 | 完整、未错位、来源一致 |
| F 润色与召回 | 候选、裁决、补丁、跨载体影响列表 | 未决项不丢失、改动可回滚 |
| G 实装与交付 | 构建 manifest、运行证据、覆盖报告 | 发布检查通过，范围说明完整 |

## A. 盘点：在翻译之前把范围数清

填写 [project.yaml](templates/project.yaml)。记录引擎及分支版本、插件/宏、原文编码、目标语言、字体/窗口、动态文本入口、打包方式、存档约束。

按载体列清单：正文、旁白、选择肢、姓名、系统 UI、存档标题、物品/技能/任务/敌人/地名、图片字、影片字幕、语音独有内容、游戏内书籍、隐藏/不可达文本。每项有 include/exclude/deferred 状态与依据。

原文基座只读；保留原包及解包指纹。明文是源码时验证原样构建/运行；是反编译产物时增加编译往返和差异解释。**字节相同仅在格式确定且允许时要求；压缩时间戳等差异可规范化，但不能把语义差异一起抹掉。**

交付四件：可运行原版、资产清单、范围文件、已知未知项。不要把“主目录扫完”误写为全作清点完成。

## B. 先做中文纵向切片

挑 5–15 分钟左右、包含普通对白和至少一个危险点的片段；时长只是起点，可按作品调整。危险点可选分支、动态姓名/ruby、图片选项、长文本、语音机关或存读档。

把少量试译从账本回写，加载中文字体，构建测试版并实际运行。测出窗口的像素边界、换行/等待标签、变量替换、字形缺失、backlog、选择按钮、存档恢复。记录这些规则的实测证据，形成 adapter 合约。

“中文能显示”不算通过全部切片：还需确认未改控制逻辑，保存后能继续，测试跳转/解锁不会混进发布版。保留一份正常游玩进入的存档；注入状态直达场景只能证明局部演出，不证明流程可达。

## C. 建三个不同层次的身份与上下文

**文本身份、执行位置、出现次数分开。**

- `text_id`：版本内稳定的可译位置；有原生 ID 就利用它，但登记基座版本。没有 ID 时，用文件/标签或地图/事件/页/命令定位，加结构摘要与源串 hash 做迁移校验。
- `occurrence_id`：这句在某条路径、某个状态、某次运行中的出现。重复执行不能为了“每 ID 一次”而丢失。
- `family_id`：回声、固定 UI、相似句、母题等关系；不是字符串相同就必须同译。

字段至少包含：源串及 hash、文件位置、说话人候选、场景、文本类型、控制码结构、分支条件、前后文、资源引用、证据、未知项。原文换版时先匹配身份与 hash；一对多/多对一单列裁决，不能按行号强迁。

维护三种图：控制流（允许环和调用）、场景/资源关系、文本派生关系。翻译用阅读序只是图上的一种遍历，互斥分支必须标隔离；将有环图压成 DAG 仅可作为经过说明的摘要视图。

提取完整性采用独立交叉检查：语言字符串扫描/原生翻译导出、适配器账本、运行时显示记录、图片 contact sheet/OCR 清点互相对账。OCR 只给线索，按原图确认。未知指令不得默默跳过；没找到静态调用不能直接证明死代码。

## D. 先冻结一个小骨架，再做有代表性的试点

没有原作梗概卡，就按场景写有来源的摘要。骨架包括：人物/别名/称呼矩阵、角色口调的短正反例、少量高杠杆术语、叙事层级、伏笔/回声族、时间轴与知识状态。只冻结已裁定部分，未决项显式保持未决。

**区分译者知道、角色知道、玩家此时能知道。**全作真相可供译者查，但输出不得提前实名、补身份、补动机或替原文消除刻意歧义。摘要也要带 branch/reveal 条件，不能把两条互斥路线缝成同一过去。

试点不要只取序章。取普通对白、深层前情、互斥分支、匿名人物、图像/声音决定取义、UI/动态文本、极端排版各类；可从 200–500 个文本单元起步，复杂演出按场景计。再用一个自然连续场景验证阅读感。

比较方案时固定源版本、输入、工具权限、模型请求配置、可见文件与检索范围。模型返回的自我介绍不能证明实际后端版本。记录服务端返回的标识（若有），无法核实时写 unknown。

评价至少分开：实义错误、身份/知识泄露、控制码与错位、自然度、演出/母题保留、图中文字、实际排版、编辑耗时。报告分母、样本范围、未完成对照与不确定性；单次实验差异不自动解释为因果。

## E. 每段生产循环

1. 冻结本段 source、当前 effective 译文、术语/口调/裁决、相关场景证据、prompt、适配器版本和构建版本，生成 context manifest。
2. 按自然场景/分支切批。一个会话可以交多批，但交付批和 API 调用分别记账；窗口或行数上限通过试点校准，不照抄本作 ≤10 批/≤600 行。
3. 初译输出只按稳定 ID 交候选；提出疑问时指向证据。缺少画面决定的宾语，就提出取证需求，不能靠“最顺口”填空。
4. 机械校验查 ID 集合、空串、错位、placeholder 的类型/数量、标签语法/嵌套、源 hash、字体和实际排版。控制符是否可移动由 adapter 定义，不套通用“数量差不多”规则。
5. 复核看原文、场景证据及现译；高风险句给证据与备选。全段通读检查重复密度、节奏和口调。
6. 收到明确完成回执后封卷：临时文件写完→原子重命名→完成标记＋内容 hash；工作进程结束/idle 只是辅助条件。封卷后修改必须发新 revision。
7. 唯一写入者核对校验记录和内容 hash，将通过的初译追加到正向线。补丁带 expected-effective-hash；底本已变则拒绝陈旧候选覆盖。
8. 生成进度、未决项、下一段所需裁决。恢复时由持久数据推导断点，不能靠聊天里的“已经完成”。

上下文优先放当前场景、必要前因、角色/受话对象、合法分支状态、关联资产、既有定译和同族句。远处摘要按需检索；不要默认每批喂完整历史。摘要每条重要事实保留来源，避免压缩把推测升级成事实。

## F. 候选、裁决和召回

保持 `source → forward → decisions/patches → effective`；下游只读 effective。源脚本不要变成多人直接编辑的翻译数据库。单人小项目可以用 JSONL 和单写者；并发扩大后使用事务数据库或队列，不把裸 append 当原子事务。

裁决动作允许 keep/adopt/edit/defer。保留候选 hash、旧译 hash、编辑理由和证据。重复提交应幂等；“改判回原稿”也要有事件记录。自评分只用于排序，不直接授予免检；模型多数意见也不能覆盖脚本事实。

术语变化按作用域发召回：先找 source/effective 中相关词及指称，再看同族、派生标题/按钮/图片/攻略、字体字集和测试引文，落补丁、重生成、重验证。多义词允许按角色/语域/路线分立，不强制进入字面匹配表。

每段抽取少量真实编辑判例：错在哪、改了什么、为何保留某个“不自然”形式、在哪种条件下适用。更新规则前检查是否与已有口调/锚点冲突。只把跨场景确实有用的规律变成常驻 prompt，防止规范越积越长。

## G. 美术、构建与验收

含字资产逐张登记源图、可见状态、文本框、中文来源、字体、渲染配方、输出 hash、验收截图。亮暗/选中/虚化等状态可从共同主版派生，前提是原作确实共享内容。选择肢文字以真实按钮/脚本绑定取证，不能由后续场景标题猜。

构建使用只读 base＋有序 patch/overlay＋manifest；目标锚点数量不符、原文 hash 不符、缺字或漏译应显式失败。test/release 用独立目录，输出记录源码、译文、资产、字体、工具和参数指纹。只重建受依赖影响的资产。

验收分四层：

- **结构**：非文本控制流和变量/跳转不意外改变；所有范围内条目有状态。
- **语言**：语义与母题、分支知识、动态插值、口调、段级节奏。
- **画面/声音**：真实字号的可读性、遮挡/裁切、控制码时序、音画信息一致或刻意不一致。
- **游玩**：正常路径进入、选择、回看、跳过、自动播放、保存/载入；列出平台/版本和已覆盖状态。

已知正确样本用于测误报，刻意损坏样本用于测漏报；规则未执行要显示 `not_run`。自动图像 diff 对汉化文字区域可做掩膜，但不能连同按钮、角色和演出区域一起忽略。

发版时附 coverage 与已知问题；不要把“没有报错”写成“所有路线都玩过”。停止条件是约定覆盖与问题级别达标；不是要求模型永远找不出更顺的措辞。

## 引擎适配边界

| 引擎 | 优先接入面 | 必须专项确认 |
|---|---|---|
| Ren'Py | 原生 translation units、strings、`tl/<lang>/` 资源和语言样式 | Python 插值、screen/UI、自定义 say、动态串、voice/rollback、ID 随原文修改的迁移 |
| 吉里吉里/KAG | 场景文本、标签/宏展开、控制标签、TJS 调用、图层资源 | 自定义宏及插件、动态跳转、条件、ruby/等待、存档和字体；krkr2 不等于每作都用同一 KAG 版本 |
| NScripter 系 | 先确认具体发行引擎/兼容实现，再建立标签、文本与命令解析器 | 源编码、字节/字符限制、文本拼接、自定义命令、字体和存档；不默认 ONScripter 与原版逐行为等价 |
| RPG Maker/WOLF | 事件页、公共事件、数据库与运行轨迹 | 页激活、开关/变量、动态文字、并行演出，见 [RPG 方案](rpg-workflow.md) |

Ren'Py 已提供对白、界面串、图片与样式的翻译机制，优先利用原生机制，外部账本负责版本和裁决；对话块并非必须一源句一译句，因此 adapter 应核对单元和控制语义，而不是全局强制行数相等。[官方 translation 文档](https://www.renpy.org/doc/html/translation.html)

KAG 的标签/宏与脚本调用需要进入解析范围；只提取标签外的文字会丢失条件和显示语义。[KAG 官方标签参考](https://krkrz.github.io/krkr2doc/kag3doc/contents/Tags.html)

NScripter 的具体实现细节本次未从可访问的官方文档核实，上表是适配器的调查任务，不是对任意版本的兼容保证。

## 最小启动顺序

第一次工作时只完成 A/B：范围文件、原版可运行、一个中文切片。第二步为这个切片建 source/scene packet 和完整裁决/回写链；第三步用代表性试点验证未知项和成本。以上三步通过后再铺开全文。

可复用本仓库 `pipelib/resolve/append_forward/recall/polish_*/read_*` 的设计和部分纯逻辑；移植前去掉仓库路径、ID 类型、Lua 控制码和本作字段耦合。`build_dag/gen_timeline/build_ledger/inject_lua` 要按目标引擎改造，不能直接复制后当通用工具运行。
