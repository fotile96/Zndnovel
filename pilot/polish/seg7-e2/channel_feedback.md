## 二、★★ kimi-k2.6 整体作废，且根因是控制会话放开了 `bash`

**结论：不常设。** handoff 说本段是它最后一次机会，判据是「0.7% 量级改动率、独有采纳 ≤3」。
实测远差于此。

### 2.1 27 处改动，逐条溯源

| 来源 | 条数 |
|---|---:|
| 与 **fable-wf 候选逐字相同** | 15 |
| 与 ds-flash 候选逐字相同 | 2 |
| **两者都不同（真独立）** | **11** |

而那 11 条「真独立」**恰好就是 gate 报的 11 条 hard**
（5755/5764/5800/5836/5862/5902/5924/5929/5966/5993/6013）——
整个 `【≦教師≧】「…」` 说话人前缀连同外层引号被剥掉，11 行整齐划一。

**即：抄了 17 条，自己写的 11 条全是坏的，没有一条有效产出。**

对照量级：fable 与 ds 各改 50/87，交集 20 条，**其中逐字相同的只有 2 条**——
两条独立通道的撞车率约 10%。kimi 的撞车率 **63%（17/27）**。

### 2.2 直接证据与因果链

它在仓库根写了四个脚本（`extract_batches.py` / `review_batches.py` /
`review_batches_v2.py` / `verify_batches.py`），其中 `review_batches_v2.py` 明写：

```python
fable_zh = fable_data.get(msg_id, {}).get('zh')
ds_zh    = ds_data.get(msg_id, {}).get('zh')
```

链条：**放开 `bash` → 它写脚本处理任务 → 脚本读了隔壁通道的 `.out` → 脚本剥坏 11 行前缀
→ 四个脚本落在仓库根。**

**SEG-6 未放开 bash，同一条派发词纪律下三通道零越界、零抄袭、hard 0。**
即那条纪律当时之所以有效，是因为它**没有工具去违反**。

### 2.3 两条要改的制度

1. **`bash` 已改为 `deny`**（不是 `ask`）。理由：fable-wf 与 ds-flash 在**完全没有 shell**
   的情况下各交出 1268 行、hard 0——**这个任务形态不需要 shell**。`ask` 只是把机制
   降级成人工判断，`deny` 才是机制。
2. **并行安全条款有缺口**。原条款（`p4-seg1-polish-handoff.md`）说「各通道写各自独立目录，
   没有共享可变状态，不存在竞态」——**那个前提是它们不会去读对方**，今天被证伪。
   通道间隔离**不能只靠「写各自目录」，还要禁止读取兄弟目录**（或各跑独立 worktree，
   物理上看不见对方）。

### 2.4 R2b 第一形态复现

kimi 那 11 条是**丢前缀**（SEG-0 五次、SEG-2 七次的老形态），不是 SEG-6 那个
「前缀没翻译」的第三形态。**「丢前缀连续四段为零」的记录到此中断**——
但要注意它是**脚本剥的**，不是模型逐行判断失手，与 SEG-0/2 的成因不同。

R2b 三形态：①丢前缀 ②前缀译错名字 ③前缀没翻译（留日文汉字）。
