# 术语提案 · crd（opus 车道）

> 试点期术语表冻结，本文件只做提案登记，不做裁决。格式：批次 / id / 原文关键词 / 建议译法 / 理由。

## batch 3

### 1. ≪入手済みカード≫ → ≪已获得的卡片≫（系统标签族，建议整族定口径）
- id 282（`snr_crd_1`，本批唯一一条）
- 建议：`入手済みカード` → **已获得的卡片**；同族标签一并定死：`≪キーワードカード≫` → **≪关键词卡片≫**、`≪この場面は、直哉と彩野によるカード選択シーンはありません≫` → **≪本场面没有直哉与彩野的卡片选择环节≫**（后两条不在本批，仅供整族对表）
- 理由：这三条是 crd 各 stub 脚本的**纯系统标签**，在 `data/ledger.jsonl` 里合计出现 30+ 次（`≪キーワードカード≫` 至少 20 条：512/513/514/536/631-634/637/655-658…；`≪この場面は…≫` 见 628/629/630），且会分散落进后续多个 crd 批次。若不预先统一，极易出现「已获得／已入手／已持有」「关键词卡／关键词卡片」并存的漂移。本批按 v6「カード→卡片」与教程行 17112「入手済みのカードが表示されます」的同族措辞，取**已获得**（书面、无游戏黑话味），未取「已入手」（偏网游腔）或「已持有」（贴 `hold` 变量但不贴原文 `入手済み`）。
- 附：`カード→卡片` 已在 `notes/s0f.md` batch 2 §3 提案补登 `active.json`；本条依赖该条一并裁决。

### 2. ★口径提问：ゲーム系统标签是否统一去「的」以压缩显示宽度
- id 282 及上述同族标签
- 现状：`≪已获得的卡片≫`（8 字）对 `≪入手済みカード≫`（9 字），W3 无压力；但 `≪本场面没有直哉与彩野的卡片选择环节≫` 一类长标签在 24 字硬折行（`cBrStr`）下接近上限。
- 建议：若委员会倾向紧凑系统腔，可整族改为无「的」形式（`≪已获得卡片≫`／`≪关键词卡片≫`／`≪本场面无卡片选择环节≫`）。本批**未**采用紧凑式，因为单独一条短标签压缩收益为零，反而牺牲可读性；一旦改口径，本条需随召回令回改。

## batch 6

### 1. 現国（現代国語）→ 现代文；与「古文」配对
- id 139、140（`snr_crd_0`）
- 原文：「古文と、現国が担当だった」「この前の現国の授業、_r『小説の神様』だったよ」
- 建议：`現国`／`現代国語` → **现代文**（不取「现国」这种日式缩写，也不取大陆语文课「现代文阅读」的全称）；`古文` → **古文**（已通行）。
- 理由：由加里的任教科目在 s1s 课堂段、s5f、s7f 反复出现，属于跨章高频词，不定口径会在「现代语文／国语／现代文」间漂移。本批已按「现代文」落笔。

### 2. 有休（有給休暇）→ 带薪假
- id 157、158
- 原文：「ちょうどいいタイミングだからって有休取って」／【彩野】「プロジェクト、有休……すごいね、直哉くんは」
- 建议：**带薪假**（备选：年假）。
- 理由：这两句是彩野「复述陌生的社会人词汇」的机关（她的时间停在 17 岁，"项目""带薪假"对她都是外语）。选「带薪假」是因为它比「年假」更像书面公司用语、更能保住那点距离感；若委员会偏好口语自然度可改「年假」，但两条必须同时改。

### 3. 『小説の神様』→『小说之神』★建议人工复核
- id 140
- 原文：「この前の現国の授業、_r『小説の神様』だったよ」
- 建议：**『小说之神』**（保留书名号式『』，不加注）。
- 理由：日语里「小説の神様」是志贺**直哉**的固定称号——而现实层男主正叫直哉。这句是彩野随口报课程内容，原文没有点破，按全知纪律不得加注、不得译成「志贺直哉」。但**是否为有意的姓名双关，值得人工确认**：若确认是彩师有意埋的，中文可能需要另想能让读者察觉的处理（当前译法在中文里完全看不出这层）。

### 4. 続き → 后续（锁口径）
- id 212、214、215、227、280、1860；另见已入库的 11／17／6631
- 建议：`（物語／お話の）続き` → **后续**，不用「下文／接下来／续篇」。
- 理由：这是贯穿全篇的机制词（Story 模式的「听故事的后续」、卡片做成后的提示语都用它），已在 batch 5 的系统文本里按「后续」落地；本批 crd_0 是它第一次作为**剧情台词**出现，建议随 `あらすじ` 一同进 active.json 锁死。

### 5. シンプル／簡潔 → 简单／简洁（成对锁定）
- id 249、251、252、253、261
- 原文：「シンプルだね」「シンプルに、簡潔に書く」「短く、_n簡潔に、_nシンプルに。」
- 建议：`シンプル` → **简单**、`簡潔` → **简洁**，两词分立、不互换、不合并成「简明」。
- 理由：这一段是卡片／『梗概』系统的定义场面，两个近义词被刻意并列复沓三次（249→251→253→261），中文若混用会把复沓写塌。本批已按此处理，建议登记为风格约束而非严格术语。

### 6. リノリウム → 油毡地面
- id 1879（`snr_crd_2`）
- 原文：「廊下のリノリウムに残った傷」
- 建议：**油毡地面**（「走廊油毡地面上留下的划痕」）。
- 理由：与序章 6273 已入库的「走廊上的划痕」是同一意象的两次出现（此处原文多了材质词）。备选「亚麻油毡」过于工具书、「地板」丢材质。低风险，仅登记以防后续 s7f/s8f 复现时漂移。

### 7. ★口径冲突：anchors.yaml 与 voices/*.md 对同一 id 给出不同 zh
- id 1887（本批）、185（本批）
- 现象：
  - 1887 anchors → 「把故事**铭刻**下来吧。」；`voices/naoya.md` §5 例 3 → 「把故事**刻**下来吧。」
  - 185 anchors → 「因为里面有**好多**秘密」；`voices/ayano_real.md` §5 例 3 → 「因为里面有秘密」
- 本批处理：一律以 `skeleton/anchors.yaml` 为准（按 translator_cc.md「锚点逐字沿用」），即取「铭刻」「好多秘密」。
- 建议：下次 glossary 升版时把 voices 表里的引例回同步到 anchors 定稿，避免两份冻结文件对同一句给出两种字面——译者每次都要判一次哪份优先，是纯损耗。
