## 1. 量词要选最顺口的搭配，不要一律用「个」

`个` 是万能量词，正因为万能所以最没有质感。指人尤其明显。

| 别扭 | 顺口 |
|---|---|
| 一个教师 | 一名老师／有位老师 |
| 一个少女 | 一个女孩／那女孩（多数时候量词整个可以吞掉） |

实例 #6172：`教師が一人、机の上に脚をのせていた` → 现译「**一个教师**正把脚搁在桌上」。用户明确点名这一处「太实在硬了」。它同时还有个词层问题——旁白里 `教師` 用「老师」比「教师」自然，「教师」是公文/统计语域的词。

⚠ **不要矫枉过正**：`一个人`（199 处）、`那个女孩`、`那个孩子` 都是自然汉语，不要为了避「个」去换成「一位人」这种东西。**只在「个」明显硌牙时才换。**

## 2. 句式回到汉语的 SVO，别让日语的格助词结构留在译文里

日语靠 `を／に／は` 标记成分，语序自由；汉语靠语序。**不要因为原文是 `AがBをCする` 就非译成「A 把 B C 了」，也不要因为有 `～られる` 就非译成「A 被 B C 了」。**

- 「把」字句只在**处置义**真实存在时用（把书放回去、把脚翘在桌上）——这两处是对的，别删。
- 「被」字句在汉语里带**不如意**的色彩，中性甚至好事用「被」就怪（「被表扬了」勉强，「被邀请了」不如「受邀」或直接主动说）。
- 日语被动经常只是**回避主语**，汉语的对应手段是**省略主语**或**换主语**，不是加「被」。

现状实测：全库含「被」的行 230 条（1.8%），其中 jp 确有被动形的只有 64%——**约三分之一的「被」是汉语侧自己加出来的**。比例不高，但正是这类地方最出戏。

## 3. 多用逗号分隔的短句

汉语的呼吸比日语短。一句话里塞两个以上的修饰层就该断开。

实测现状：全库分句均长 7.4 字、中位 7 字、超过 20 字的只占 1.7%——**这一条现有译文基本已经做到了**，写在这里是为了防止润色阶段为了「文气」反而把短句并成长句。**润色不得以顺畅为名合并短句。**

## 4. 连词按汉语的需要增删，不跟着日语走

顺承、递进、转折的逻辑关系，**日语常靠语气与语序暗示，汉语常要显式连词托住**；反过来日语显式写了 `しかし／だから／そして`，汉语吞掉往往更利落。

**两个方向都要做，这一条不能只做一半。**

- 日语没写而汉语该补：`……。……。` 两句之间其实是转折 → 补「可是／不过」
- 日语写了而汉语该吞：`そして` 起头的顺承句，汉语直接接着说就行

判断方法：把中文读一遍，**逻辑接不上就补，读着啰嗦就删**。不要机械对应。

## 5. 补主语、少呼名、名字出现时带同位语

三件事，都指向同一个现象：**日语句子可以没有主语，且提人名的频率远高于汉语。**

**（a）补主语。** 日语省略的主语，汉语常常补出来才顺，尤其对白。

**（b）呼名换代词。** 日语里 `彩野さん`／`直哉くん` 满天飞，汉语实际对话里没人这么高频叫名字，该用「你／我／他／她／您」。

> **实测（2026-08-04，opus 车道 6987 条对白，两侧均剥掉说话人前缀）**：
> jp 台词正文提到人名 **1553 条（22.2%）**，zh **1554 条（22.2%）**——
> **jp 提名的行里 zh 照搬了 100%（1552/1553），只有 1 条换成了代词。**
>
> 这是本文六条里**规模最大、最机械的一条**。不是偶发失手，是从来没做过这个转换。

**（c）名字真出现时带人称代词同位语。** 汉语的习惯是「彩野同学**你**」「直哉君**你**」，而不是光秃秃一个名字。

现有译文里做对了的（94 条，占照搬行的 6%）：

- #6385 「和**直哉君你们**做同班同学的高中二年级……」
- #7410 「说什么老头子似的话呀。**アヤノ你**不参加社团吗？」
- #7518 「前几天，**アヤノ你**好像，说过什么来着哦」

该改而没改的（照搬）：

- #6151 `それでね、直哉くん` →「话说呢，直哉君」（可作「话说呢，**直哉君**」保留呼语，或整个吞掉作「话说呢」）
- #6165 `彩野さん！` →「彩野同学！」（**呼唤语气，这里保留是对的**）

⚠ **不要一刀切**。三种位置要分开处理：

| 位置 | 处理 |
|---|---|
| **呼唤语**（单独一句叫人、句首招呼） | **保留名字**——汉语也这么叫。#6100「直哉君」#6165「彩野同学！」都不用改 |
| **句中作主语/宾语** | **优先换代词**，或改「名字+代词」同位语 |
| **第三人称指称**（谈论不在场的人） | 首次用名字，其后用「他／她」 |

还有一条硬约束：**片假名名与汉字名的区分是剧情机关**（【アヤノ】=故事内角色 / 【彩野】=现实人物），换代词时**不得让这个区分丢失**。所以「首次用名字、其后用代词」的首次那一下必须留住原写法。

## 6. 意思不漂的前提下，可以适当用汉语习语、成语

这是让译文「像中文」最省力的一招，也是最容易翻车的一招。

**可以用**：意思严丝合缝、语域也对得上的常用四字格与习语。

**不要用**：

- 意思稍有偏移就为了「文采」硬套——**宁可平实，不可失真**
- 带**明显中国文化专属背景**的（典故成语、朝代人物、中式称谓）——这是日本校园故事
- 语域不符的：这是高中生对白与第一人称旁白，**书面雅词会立刻出戏**
- 绘本段（b123）**一律不用**——目标读者是学龄前，见 `style.md` 童谣体一节

### 7.1 opus 车道的排除已落盘，不依赖任何人记得

用户 2026-08-04 要求：**接下来 opus 的重冻结不得带上本文**。这已做成机制，不是纪律：

```
pilot/lanes/opus/lane.json → "freeze_exclude": ["glossary/polish.md"]
```

- `setup()` 建/重建车道时按此列表**不拷贝**该文件；
- **未显式传 `--freeze-exclude` 时继承车道现有设置**——所以段边界 `--force` 重冻结照样排除，操作者不需要记得加参数；
- 要解除，显式传空：`--freeze-exclude ""`（「不传」与「传空」刻意可区分）；
- 排除项路径写错会 **stderr 告警**（少排一个文件从产物上看不出来）；
- `--verify` 每次单独播报一节「ℹ 有意排除 N 项」。**排除不从落后清单里被 skip 掉了事——跳过等于藏起来**，而藏起来的机制正是本项目反复吃亏的形态。

改动落在 `tools/lane_setup.py`：`lane_exclusions()` / `set_exclusions()` / `setup(freeze_exclude=)` / `frozen_exclusions()`，CLI 加 `--freeze-exclude` 与 `--set-exclude`。六个变异全部被测试抓住（继承失效／不真删／被当成落后／不播报／set 不删已存在文件／打错字不告警）。

⚠ **接入点 A 落地时仍要复查一次**：A 一旦实现，「哪条车道看得见」由该车道冻结拷贝里有没有它决定。fable 车道**没有**这条排除（有意如此），建车道时会自然拿到；opus 要改主意就解除排除。`--verify` 的两节输出会把每条车道的实况列出来。

**建议**：先走 **A + D**（生产端要求 + 润色端兜底），**C 暂不动**——让语感问题统一由润色轨收，而不是让评审在正文轨里逐批争论顺不顺口。

**为什么 opus 暂不接入**：SEG-1–4 已按现有 `style.md` 译完，中途换口径会在段边界留下风格断层，而全篇统一本来就是润色轨的任务——让润色一次性铺平，比让正文轨半途改道干净。

⚠ **本文不设机械闸，且不应设。** 六条全是语感判断：「量词顺不顺口」「连词该不该补」没有可判定的谓词，硬做只会得到一个满口伪报的检查器——本项目已经吃过一次亏（ruby 自洽判据过宽，104 处报警里 99 处是伪报）。**唯一例外是第 5 条（b）**：「jp 台词正文提到人名而 zh 照搬」是可机械清点的，可作**顾问级提示**（列出候选行交人判断），**不得**做成通过/不通过的闸。
