### §0「抓出错译」：有效，且抓到了机械闸查不出的东西

| 通道 | 569 行产出的 `adjudicate=true` |
|---|---:|

SEG-1 全段 1992 行只有 2 条主动请裁；fable-wf 在 569 行里给出 3 条，**请裁率约 5 倍**。
三条都不是凑数：

- **6174** `【教師】「あー！ はいはいはいはい！ 彩野さんと一緒の方ね。…」`——教师是**看见彩野
  才认出来人**，这个 `はいはい` 是恍然认出的应和，opus 的「好好好好」读成应承/敷衍义。
  与 SEG-1 的 8778 是同一取义分岔，说明 §0 点名 `はいはい` 点对了地方。
- **6253** `不気味` → opus 作「**渗**人」，正字「**瘆**人」。**这是错别字不是错译**——不在任何
  术语表里，机械闸查不出，只能靠通读日文时发觉。详见下面第三节。
- **6189** `ほどほど` 撞上 v13「还行族」定译的**构式边界**：该条明写只管 `〜って所／と
  言ったところ`，本行是 `〜という感じで`。是真的判据留白。**建议 v15 把近旁构式是否入表
  写明**，否则每撞一次就要请裁一次（通道自己也提了同一诉求，见下 F6）。

### §5(d)「判断单位是上下文」：fable-wf 守住了，ds-flash 推平了

fable-wf 的 32 条改动里 **28 条是叙述行**；4 条对白改动**全部不是**呼名换代词，而是词汇
修正（`はいはい`/`ワクワク`/同级生/值日生）。对白呼名一处未动。

ds-flash 未纠偏时改了 112 行（19.7%），其中 **92 条是呼名换代词**，且推平了本段的演出机关：

```
[6342] 【直哉】「彩野同学受到的那个『损伤』，我来说明一下」 → 「你受到的…」
[6412] 【直哉】「彩野同学的话，大概是『15分钟』」          → 「你的话…」
[6387] 【彩野】「现在，站在我面前的直哉君，是23岁」        → 「站在我面前的你，是23岁」
```

**6387 是最清楚的反例。** 上下文 6385→6387→6389 是彩野在**逐条复诵事实来重建现实**
（「不是17岁。不是同班同学。我也，23岁」）。`直哉くんは２３歳なんだ` 是 `〜は…なんだ` 的
**事实断定**，她在把一条命题按进脑子里，不是在称呼对方。换成「你」，自我确认就塌成普通对话。

**本段的呼名重复往往是演出机关本身**：重度前向性健忘题材，直哉刻意反复呼名当记忆锚点。
fable-wf 自己在反馈里点出了这一点（下 F4）并据此克制；ds-flash 机械套用 §5(b)。

⚠ **这是契约缺口，不只是通道差异**：§5(d) 说了「判断单位是上下文」，但**没有说
「名字重复本身可能是演出机关」**。fable-wf 靠推理补上了，ds-flash 没有。
**建议下一个 SEG 的 polish.md 补明此条。**

### 派发词纠偏可以压住——实测有效

s2–s5 派发时给 ds-flash 加了四条纠偏（写在派发词里，prompt 已冻结不能改），
其中三条直接引用它自己 session 1 的失败。四个会话对照：

| 维度 | s1（无纠偏） | s2 | s3 | s4 |
|---|---:|---:|---:|---:|
| 行数 | 569 | 508 | 597 | 431 |
| 改动率 | 19.7% | 4.5% | 1.5% | 4.6% |
| 呼名换代词类 | **92** | 2 | 0 | 0 |
| `adjudicate=true` | **0** | 1 | 1 | 1 |
| 丢 `【说话人】` | 1 | 0 | **1** | 0 |

**分维度结论，不要笼统说"纠偏奏效"：**

- **纠偏 1（呼名机关）、3（§0 硬条款）、4（宁少勿滥）——有效。** 呼名类改动 92→2→0→0，
  改动率回落到 1.5–4.6%，每个会话都产出了 1 条主动请裁。
- **纠偏 2（绝不能丢 `【说话人】`）——完全无效，且随行数累积。**

  | 会话 | 纠偏状态 | 丢 `【说话人】` 的 id |
  |---|---|---|
  | s1 | 无纠偏 | 6153 |
  | s3 | 纠偏 v1（引用了 6153） | 7662 |
  | s8 | 纠偏 v2（**逐字引用了 6153 与 7662 两次失败，并写明"出一次废一条"**） | **6867、6878** |

  三轮下来共 4 例，最后一轮在最强的提示下反而出了两条。**提示层面的纠正对这条结构性
  约束不起作用。**（初版本节曾写作"压制力弱于风格性约束"，说轻了，据 s8 数据更正。）

  **代价可控但不为零**：R2b hard 闸每次都拦下，这类候选作废、进不了裁决队列——是"被抓住
  的失败"而非"泄漏的失败"，且 fable-wf 仍覆盖这些 id。但它意味着 ds-flash 在这 4 个 id 上
  等于没出稿。**结论：`【说话人】「」` 结构的完整性只能靠机械闸保证，不能靠通道自律。**
- **副作用**：s3 只改了 1.5%，明显低于 s2/s4，可能是「宁少勿滥」吃得偏重。派发词措辞会
  显著左右产出量，**这本身就是"通道行为不稳定"的另一种表现**。

**总体判断：ds-flash 不是"能力不足"，是"没有被告知本段的特殊性"——契约本文没写的东西
它不会自己推出来。** 一旦在派发词里写明风格性要求，它就照做；但结构性硬约束
（说话人标签完整性）靠提示压不牢，只能靠机械闸兜。这条对后续 SEG 的通道管理有直接价值。

## 三、实弹发现

### D1 — 「渗人」是全车道系统性错别字（3 处，跨段）

两条通道**独立**在不同 id 上报出同一个错别字，互不知情：

| id | 通道 | 现状 |
|---|---|---|
| 6253 | fable-wf | 「有点**渗**人，却又莫名让人安心」 |
| 8024 | ds-flash | 「要说**渗**人，也许确实是有点**渗**人」 |
| **11479** | — | 「就忽然显得**渗**人起来」——**在 SEG-0 之外，两条通道都看不到** |

全车道对照：「渗人」3 处 / 「瘆人」2 处——**译文自身不一致，且错形更多**。
`不気味` 的正字是「瘆人」（shèn rén）；「渗」是渗透义，属常见别字。

**处置**：6253/8024 在本段队列内，清关时一并修正。**11479 在段外**——与 SEG-1 的
W4 跨段漏网（9546↔13448、9862↔12058）是同一形态：缺陷的完整范围跨段，而冻结面只给
通道看本段。按 SEG-1 先例，跨段修正需**单独裁定**（那次的 commit 写明「是明示裁定的
例外，不是先例」）。**段末裁决时须就 11479 单独请示。**

### D3 — 工具缺口：`adjudicate=true` 但**未改动**的候选不进裁决队列

`polish_triage.py` 按「有无改动」分桶：零改动行落桶 1，不进裁决队列。于是**通道说
「我不改，但请你裁」的请求会被静默丢弃**——除非另一条通道恰好改了同一行。

本段实测 3 例：

| id | 通道 | 是否进队列 | 请裁内容 |
|---|---|---|---|
| 269 | fable-wf | ✅ | 侥幸——ds-flash 那侧改了这行，靠它进的桶 2 |
| **17002** | fable-wf | ❌ **被丢弃** | `終了` 在 17002 作「完结」、17003 作「结束」；「章节Ｎ已完结」可能有跨段同型伙伴行，不敢单改 |
| **7963** | ds-flash | ❌ **被丢弃** | 现行译文句尾「后来会怎么样呢」与**锚点 6085**「那时如果抓紧了她的手，后来会怎么样呢」同构互文；请裁这是有意呼应还是译者加戏 |

**两条被丢弃的都不轻**：17002 触及跨段术语一致性，7963 直接触及那 8 条有段外伙伴的锚点
之一。本轮已**手工并入**第二轮裁决，但这是靠人发现的，不是机制保证的。

**建议修复**（下一个 SEG 之前）：`polish_triage.py` 对 `adjudicate=true` 的候选，
无论有无改动一律强制进队列（与软锁改动同等待遇，不被 K 挤出）。理由与软锁那条一致——
「看一眼」这件事不该因为分桶判据只看改动量就被吃掉。契约明确鼓励「拿不准就照抄 + 请裁」
（纠偏 3、§0 都这么写），而当前实现恰恰惩罚了这种正确行为：**越是老实照抄并请裁的通道，
它的请裁越容易消失。**

### D2 — 6324 把「同級生」并入「同班同学」（待裁）

fable-wf 把 6324 的 `同級生` 译作「同班同学」，理由是与同段 6385/6389 取同词——
