## 3. ★ 三处台账事实经我方 grep 复核须更正

本段生产会话记录过 6 次核验方法失误，故本会话引用的每个计数都自己重跑过。查出三处：

### ① `屋台` 与 `出店` 被写成了一个词

台账 A2 表记「`屋台`（现为**小摊**）→ 小吃摊」。实际：

- **`屋台` 全库仅 1 处**（10512『屋台のライトの光』），现译是「**摊子**上灯的光」，不是「小摊」。
- 「**小摊**」是另一个词 **`出店`**（全库 8 处、6 已入线）的译法，且 `speakers.json` 的
  『出店の親父』→「小摊老板」属同族。

→ 改动范围看起来是 8 处，**实为 1 处**。已就此向用户确认，用户明确选定「**只改 `屋台`（1 处）**」。

**并据此答复用户的「附带请裁」——`出店の親父` 不连带调整，维持「小摊老板」**：
该摊是**钓水气球摊**不是吃食摊（10562『出店の水槽の前にしゃがみ込む』水槽／10564 收费
「一次，２００万日元」／10599 递气球「给你嘞，小姑娘」）。改「小吃摊老板」会与场景实物直接冲突。

### ② `水風船` 本来就已正确分写 → **零 patch**

台账 A2 表记「现译：钓水气球 → 改为：水气球」，并标 ⚠「须分两项，请逐 id 指定」。
逐 id 核对 forward 后：**两形本来就已经分对了**——

| id | 原文 | 现译 | 判定 |
|---|---|---|---|
| 10547 / 10558 | `水風船釣り`（游戏名） | 钓水气球 | ✅ 正确，勿动 |
| 10610 / 10647 / 10702 | `水風船`（物） | 水气球 | ✅ 正确 |

→ 「逐 id 指定」的结论＝**维持现状，不发任何 patch**。若照表面执行「一律改水气球」，
反而会把 10547/10558 的游戏名改坏。
（`水風船`→水气球 仍入 active.json：核心串单值，`水風船釣り` 含之，一条即覆盖两形；剩 e2f 5263。）

### ③ 「三词三义」不成立（`グラウンド`/`校庭`/`運動場`）

台账复议①称三词三义。逐条核对已入线文本后，实际是**三个原文词共用两个中文词、映射尚未稳定**：

**「不合并」的结论仍然成立且理由充分**——6130『グラウンドを校庭の隅…から眺めていた』

## 6. ⚠ 新发现的一条冻结面缺口（移交开发轨）

`lane_setup.freeze_hashes()` 只哈希 **5 项**：`batches` / `cards_zh` / `anchors` / `active` / `glossary_max`。
而 `COPIED_DIRS = ("skeleton", "glossary")` 会把 **`speakers.json`、`style.md`、`voices/*.md` 一并拷进车道冻结**。

→ **这三类文件被冻结、却不在 manifest 哈希里，`--verify` 结构上检测不到它们的漂移。**

本段之前这是纸面问题；**本段之后不是**——v9 恰好改了 `speakers.json`（**R2b 硬规则的数据源**）
与 `style.md`（译者唯一能看到的口径面）。若日后有人在仓库侧改了 speakers.json 而忘了
`lane_setup --force`，`--verify` 会照报「无漂移」，而车道仍按旧表校验，且**没有任何信号**。

建议（不在本会话做）：`freeze_hashes` 增补 `speakers`、`style`、`voices`（目录哈希）三项。
属 §4.1 判定表里「不在 canary 覆盖面、须人工判定」的一类，改动只影响 manifest 内容不影响批次产出。
