### 7 月 31 日至 8 月 2 日：试点验证流水线，同时暴露评价方法的边界

opus 35 批、4,282 行实际完成；fable 只有 batch 1，不能宣称完成双模型对照。`8cad4a8` 的[报告](../superpowers/reports/2026-08-01-p2-pilot-report.md)记录 32/32 锚点遵从，但母题句族仍可漏锁；窗口边界的稳定也可能来自检索补偿，不能证明压缩无损。

试点发现的主要问题是：消息 ID 顺序不是演出顺序、术语子串检查误报、原文合法重复误判崩溃、口调例句与锚点互相冲突、不可达文本与普通剧情混排、模型自述可能虚构规则。容器回收后靠逐批提交恢复，也证明了检查点的实际价值。

`c9d6e01` 以 v7 裁决和召回收尾。**试点的产物不仅是译文，更是一份“当前流程能证明什么、不能证明什么”的清单。**

## 2. 应带走什么，哪些只保留思路

| 层 | 本项目资产 | 下一项目的处理 |
|---|---|---|
| 原文与版本 | ledger、forward、patches、resolve、hash | 优先移植契约；原子 append 加事务与并发控制，不能假定当前脚本已经是多写者数据库 |
| 叙事骨架 | 梗概、口调、anchors、路线 | 用“场景摘要＋人物关系＋知识状态＋母题族”替代本作卡组；保存分支条件 |

## 3. 本历史里最有价值的反面教材

1. **文档不等于现状。** `CLAUDE.md` 仍保留“仅初始 commit/尚无测试体系”的早期段落，总 spec 的 P4 还指图片阶段，实际 P4 已是润色。新项目维护简短现行契约，旧 spec 明示被何版取代。
2. **绿灯必须有分母和执行状态。** 不读取冻结面、零数据、未启用规则、不可解析，都可能伪装为“零问题”；至少输出 pass/fail/not_run/unknown 及处理数量。
3. **一致性不等于机械同串。** 同句可因分支、说话对象而异；异句也可能是必须保持的回声。族关系要带类型和作用域。
4. **评价必须隔离答案。** 自述、模型名、自评分、一次小考、改动率都不能直接等同质量。检索是否开放、调用包装、对照数据是否可见要登记。
5. **一份原始证据应服务全部载体。** 正文改词，卡面、选项、攻略、测试题、字体和截图也可能过期；召回是依赖传播。
6. **先实装一个切片。** 该项目在全文翻译和多轮润色后才深入证明回编/排版/存档，下一项目不必重走这个顺序。

截至基线，当前正文账本和 opus 正向线各有 16,749 个唯一 ID，extra 账本 878 行；这些只说明当前提取/入线规模，不代表所有运行路径、多媒体和平台已穷尽验收。早期 spec 的 16,750、extra 的 829 等应按各自时点阅读。
