> 起因：用户实测发现 `snr_e2_10_f` 里 id 4838 起一组以 `≪≫` 括住的对白，**配音念的不是字幕上的话**，

## 0. 结论

- **全库只有这一处**：字幕与配音念的是两套台词的行，恰是 e2f_50 的 4838–4847 十行（4848/4850 起字与声合流）。
- 其它「说话人标签与配音演员不一致」的有声行（共 90 余行）全部是**换人不换词**或**职能标签**
  （【男子生徒】【教師】【＊＊＊】等），配音逐字就是字幕（差异仅标点、假名/汉字写法、不足一秒的气声）。
- 全库 `≪≫` 共 173 处，**只有这十行是把整句对白括在 `≪≫` 里的**；其余是卡片系统提示（≪キーワードカード≫ 等 71 处）、
  句内强调（『たとえ≪途中で…≫』等）、以及标签位的 【≪彩野≫】【≪ユウイチ≫】（现实层顶替，全部 NONVOICE）。

## 3. 演出结构（解读，非事实）

- **文本层**是雪乃写的『物語』：サクラ和「ユウイチ」在医院中庭闲聊他和アヤノ约见的时间。
- **声音层**是另一段真实发生（或真实应当发生）的对话：直哉终于向"她"坦白自己不是ユウイチ——
  「不太对」「我本该更早察觉」「因为我没有认真去理解你」，她从「你有约吧」到「诶？什么意思」到「ユウイチさん……」，
  最后一问一答（4848/4850）字与声**合流**——故事被迫承认现实。
- 声优分配与本作既有设定一致：现实层里「サクラ」的声音一律由千秋的声优 CHI 出（s7f 16367 【サクラ】『アヤノさんっ！』
  也是 CHI02770），反过来千秋口中出现雪乃的声音时用 SAK（s8f 16603/16605）。故这里 CHI 配≦サクラ≧不是随手换人，
  而是"现实层的她"。
- 框架呼应：e2f_10 结尾 4795–4797「把缠在播放器机身上的线解开／把耳机塞进两只耳朵／按下播放键，把音量调大」——
  雪乃是**戴着耳机听着什么**在写这段故事的；玩家从 4838 起听到的"另一套话"，与这个动作同构。
- 脚本层面的分界：4834 之后 `cStopBGMWrap` → `mus_26` 单次播放 → `comEffectYellowIn(60)` → 四声 SE（se_101/102/101/51）
  再进 4835；4843 后再补一声 se_101。除此之外**没有任何画面提示**告诉玩家"字和声不一样"，全靠耳朵。
- 这十行的语音 id 不是 NORECORD，backlog 里照样只有字幕文本——原作也没给不懂日语的人留任何文字通道。

## 5. 汉化版怎么呈现（已裁定：C，`「」` 壳）

前提事实（引擎，见 `docs/ops/eboot-kinsoku-research-2026-09-04.md`）：消息窗 4 行 × 425 px，`_r` 换行、`_n` 只是等键；
ruby 组不换行、base 须 `col + n_base ≤ 25`、base/ruby 各 100 B 栈缓冲。

| 方案 | 做法 | 评价 |
|---|---|---|
| A 原样 | 字幕译故事版（现状），配音日文原声 | 零工作量。不懂日语的玩家**完全感知不到**这个演出——而它是这一章的机关；`≪≫` 壳本身在中文里不传达任何信息 |
| B ruby 叠加 | 把配音内容用 `<字幕,配音>` 作小字注在字幕上方 | **不可行**：4840/4842 字幕超过一行，ruby 组不换行；且配音内容比字幕长时注音会越出 base 宽度 |
| C 同框双行 | 字幕照旧在 `≪≫` 里，`_r` 换行后加一行配音内容，用一个提示壳区分 | 排版模拟：十行全部 ≤3 行、零告警（见下）。backlog 里也两行都在。是编辑性增补，但这是不改引擎的前提下**唯一**能把演出送到中文玩家眼前的办法；本项目已有「（译注：…）」先例 |
| E 只在攻略里说明 | 攻略 EX2 段加一句"此处配音与字幕不同，是有意的" | 便宜，但玩家读到时多半已经过去了，且攻略不该替游戏讲故事；可作 C 的补充 |

**采纳 C，第二行用 `「」`（用户裁定）。** 理由：`「」` 是全篇正常对白的壳，读者天然把它读成"说出口的话"，
与 `≪≫`（故事里写的）形成对照；到 4848/4850 原文本身换回 `「」`，≪≫ 那一行消失、只剩「」——合流在版面上自然显现。
落地形制：`【≦Yuichi≧】≪字幕现译≫_r「配音内容」`，`≪≫` 内一字不动。曾考虑过的 `（耳机里：……）` 与 `≦……≧` 壳均未采用。
