## 3. 跨阶段真正存活下来的方法论内核

反复出现、且在不同载体（正文/UI/图/二进制/攻略）上都成立的规则，按出现频次排序：

1. **原始资产只读，改动全部成层，产物可从「基座 + 层」随时重生成**。从 `work/` 丢译文事故（阶段 0）到层管线（阶段 4），这条规则一路升级。
2. **「恒绿」是头号敌人**。canary 不传 siblings 等于没跑、`detect_collapse` 恒返回 0、`resolve` 不给目录静默算出空表、UI 术语闸反向运行 9 天、`getbbox()` 在 RGBA 上只看 alpha 让断言永远绿、发布断言自己跟自己比。对策统一：**每道闸配变异/播种自检；认不出的输入必须出声；「无法判断」是一等结果，不得坍缩成 clean。**
3. **只追加入库 + 唯一清关口 + 默认演练**。forward/patches、保税仓、通读草稿、裁决草稿都遵守；可撤回；按键幂等。
4. **冻结 → 锁版 → 段末小裁决 → 版本化召回**。骨架冻结、段内 glossary 锁死、tag 钉生产树、召回令可见（recall-must-be-visible）。
5. **上下文按玩家经历顺序拼，远处 compact、近处全文**。本作借游戏自己的『あらすじ』机制，其他作品要自己造梗概层。
6. **人的决策做成可登记的裁决**：对照图拍板 → 裁决编号 → 配置即持久记录；成族改词先列表复看再 commit。
7. **外部视角做质检**：只读译文的外部模型做理解测验（反剧透闸）；玩家/朋友反馈原样入草稿再分档复核。
8. **玩家反馈 → 根因 → 常驻校验器或回归测试**，而不是只修那一处。
9. **换底层工具链先做逐字节可复验的等价验证，再全面查下游静默降级。**
10. **每段写台账、交接件、被推翻的结论显式记录**；裁决纪要跨段传递要**验证它真的到了下一段**（runbook 写着自动带过去、实际是假的）。

## 4. Quick Start Pack：明文脚本 VN（Ren'Py / KiriKiri / NScripter）

### 4.1 不带走的（胎盘清单）

以下在本作是必需器官，迁移时随出生丢弃；pack 里只留一句检查问题「你的胎盘长在哪」：

| 本作胎盘 | 它服务的本作事实 | 新项目的对应检查 |
|---|---|---|
| 反编译基座逐字节等价、`luac_norm` | 脚本是字节码反编译产物 | 明文脚本：改为**零翻译往返恒等**（解析→写回逐字节一致） |
| 手抠章节调度器重建 DAG | 调度器藏在 lua `main()` 状态机 | 明文引擎能执行：用**执行轨迹**（§4.3 Day 2）或 AST 建图 |
| EBOOT 字节补丁（禁则/像素/存档） | 引擎闭源、固件级限制 | 问一句：排版与存档限制能否用引擎配置或脚本层解决？不能才上二进制 |
| PGF 字体头部 ascender、字集裁剪 | PSP 字库格式 | TTF 直接用；但**字集从最终脚本推导并溯源**这条保留 |
| GIM 模板回填、索引 0 透明 | PSP 纹理 | PNG 直接替换；「先清点→测绘→渲染，用独立证据核清点」保留 |
| 『あらすじ』卡面即 compact 语料 | 游戏机制送上门 | 需自己生成梗概层（按章/按 label 段），作为前缀压缩单元 |
| UMD 就地替换、iOS 变体盘、SOUND.BIN | 光盘与平台 | 发布 = 打包目录或 patch；但「发布剖面与测试剖面分树」保留 |
| 层叠加 toml（锚点=代码文本） | 基座不可改且需逐字节等价 | 降级为 **quilt 式 patch 队列**（git diff），manifest 只留顺序表 |

### 4.2 目录骨架

```
<project>/
  base/            原始脚本与资产（只读，测试钉住恒等）
  analysis/        提取产物：dag.json、text_digest/、trace/（§4.3）
  data/            ledger.jsonl（原文账本，稳定 id）、timeline.jsonl、batches.jsonl
  skeleton/        梗概定稿 + anchors.yaml（冻结带 tag）
  glossary/        glossary.vN.yaml（append-only）、active.json、speakers.json、style.md、voices/
  lanes/<name>/    forward.jsonl + patches.jsonl（入库！不要放 gitignore 目录）
  layers/          manifest.toml + patches/*.diff（或引擎原生覆盖：Ren'Py tl/、KAG patch.xp3、NScripter 覆盖脚本）
  tools/           §4.4–4.7 的工具
  tests/           每道闸一个变异自检
  docs/ops/        台账、交接件、裁决记录（runbook 模板见本文）
  build/           一切产物（gitignore）
```

稳定 id 取法：Ren'Py 用引擎自带 translate identifier；KAG 用 `文件:*label:段序`，再加原文 hash 防重排；NScripter 用 `文件:行:段序` + 原文 hash。**行号不是稳定锚**（本作换基座时全体漂移），任何键里都要带内容 hash 或引擎自己的 id。

### 4.4 常驻闸（按载体）

| 闸 | 规则 | 自检 |
|---|---|---|
| 往返恒等 | 零翻译 emit 与 base 逐字节一致 | 改一个字节必须红 |
| id 唯一与全覆盖账本 | 两套识别器口径一致；**凡是没进账本的文本注入时报不出「缺译」**（本作 51 行黑洞） | 删一行账本必须报 |
| 控制码保真 | 换行/ruby/变量/等待码原样 | 删一个控制码必须红 |
| W4 复现句族 | 同一日文的复现句译文逐字一致（豁免清单 W4） | 改一句必须红 |
| 崩溃探测 | 假名残留、长度比、复读；**以原文重复度为基线** | 恒返回 0 必须被测试抓到 |
| 术语命中 | active.json 为字面核心串；登记前先对已有译文测命中率 | 删一条必须红 |
| 排版 | 按引擎实际规则模拟（Ren'Py 可直接渲染量宽；KAG/NScripter 按字宽表 + 禁则） | 超宽一行必须红 |
| 冻结面漂移 | 骨架/口调/style 的 hash 进车道冻结清单 | 改 style 必须红（本作漏过） |
| 发布断言 | 发布剖面无测试捷径；产物带输入与工具版本 hash | 混入测试层必须拒绝 |

### 4.5 生产循环（每检查段）

1. **锁版**：glossary vN、骨架 tag、工具 tag（worktree）。
2. **会话组生产**：一条长对话连做 ≤10 批/≤600 行；style 每批重投，口调表只投一次；每批出译文 + 手记（术语提案、伏笔疑点）。
3. **段末机检**：全部闸 + canary 回归。
4. **外部理解测验**：廉价模型只读梗概前缀 + 本段译文，题目**从原文出**，前缀过反剧透闸（只给严格早于本段的信息）。
5. **用户抽读 + 交接件**。
6. **小裁决**：手记提案聚类 → 饱和度 ≥0.8 的词族才裁 → glossary vN+1 + 召回令 → 回改走 patch → 重新冻结。**成族改词先列 `id|原文|改后` 表复看，点头再 commit。**
7. **裁决纪要显式传递到下一段**，并在下一段开头验证它到了。

### 4.6 审校（稀疏化，而不是逐行 40 万字）

- **两轮翻**：第一轮「盲玩档」= 正常前缀翻译；第二轮「二周目」只碰锚点与「伏笔→回收」配对的 setup 端（约 1–3%），两轮 diff 即伏笔清单。二周目改动必须过**泄底测验**：全知修订版若让读者模型「预判后文真相」答对率明显高于盲玩版，说明暗示写太明，打回。
- **读者模型举手**：只读中文、没见过原文的模型按路线序通读，举手必须写四样（类别 / 引文 / 我本以为会读到什么 / 严重度），写不出「本以为」的丢弃；同段两独立样本取交集；每场景 top-k 预算。
- **承重风险**：「通顺但译错」读者看不见。因此 **C 档（语义偏移）召回必须单独算**；低于约 0.4 就不能用举手代替逐行，要补「沉默区抽检」：未举手行分层随机抽 ~1% 给看得到原文的模型/人，估漏检率上界作为整章停止条件。
- **人设崩专项读者**：只给公开人设卡（自称/语尾/礼貌层级，剔剧情），专抓「这不像 X 会说的话」，单独算精度。
- **品味语料迁移**：把上一作的人工批注与裁定脱敏（专名→角色功能占位，道具→〈母题道具 n〉），保留为（句型, 改前, 改后, 裁定, 理由）五元组而非条文；守门：对旧专名表 grep 0 命中，抽 20 条让模型猜出处接近随机。
- **外部审读**：朋友/玩家修改**原样入草稿** → 三档复核（A 误字术语 / B 不通顺 / C 语义偏移）逐条裁定 → 单行走清关口、成族或锚点走 glossary 新版 + 召回。

### 4.7 发布与验收

- **基座 + 层 + 剖面**：release/test 分树；test 剖面可带「直入任意 label」「全解锁」捷径；release 断言拒绝任何测试层。
- **发布前过闸再出包**（秒级 check 与分钟级 build 分开）。
- **自动驾驶验收**：Ren'Py 有 `renpy.exports` 与 dummy 驱动可无头跑全路线截图；KAG/NScripter 走窗口自动化（按键注入 + 截图 MSE 比对）。首帧、每章首屏、每个选项画面各一张基线图。
- **玩家反馈 → 根因 → 常驻校验器**（本作：攻略 5 处流程错误 → 路线重放校验器；7 字空白 → 字集依赖建模）。
- **每个被推翻的结论显式记录**（本作同一天「iOS 无解」→「实验推翻」）。

## 5. 2D RPG（RPGMaker / WolfRPG）端到端翻译工作流建议

### 5.1 问题的本质

RPG 的「刚发生了什么」不写在文本里，写在**状态变化**（开关、变量、道具、队伍）与**指令流**（移动路线、气泡、闪屏、换装、战斗结果）里；「谁在说」往往没有名字框，靠脸图、朝向、触发者等同帧旁证。所以字符串表级翻译的两个系统性错误是：**人称/敬语/性别选错**（中文必须硬选，日文可以含糊）与**语气与演出相反**。目标不是让 LLM「看懂画面」，而是把演出**编译成机读的舞台提示**，再让 LLM 翻。

### 5.2 架构（七层）

```
① 静态清点      Map*/CommonEvents/Troops/Actors/System.json（WolfRPG 先经解包器归一化到同一 IR）
                 → 每事件每页 + 页条件 + 指令序列；文本单元 101/401/102/105/108；分支 111
② 运行时轨迹    插件包住 Game_Interpreter.executeCommand、Game_Message.add、setupChoices、
                 开关/变量/gainItem setter；记 mapId/eventId/page/cmdIndex、坐标、朝向、在场者、队伍快照
                 驱动：传送到事件旁 + event.start()，不做寻路；每个分支点存档 fork
③ 切拍 (beat)   以每条 Show Text 为界，收集上一拍到本拍的非文本指令与状态差分
④ 导演备注编译  确定性规则表（§5.3）→ 【获得：古い鍵】【X离队】【A 转身背对 B，气泡：汗】【停顿约 2 秒】
⑤ 归属层        speaker/listener 各附证据分（§5.4）；拿不到强证据 → speaker=?（合法状态，停人工）
⑥ 前缀组装      「剧情时钟」变量（单调递增、被大量页条件读）当时间轴；支线挂在触发区间；远处用梗概 compact
⑦ 翻译 + QA     system 放图例/术语/三条硬规则；user 放台词与 stage 交错的 JSON；舞台提示反过来做译后 QA
```

全量台词都能从 ① 静态出提示；② 只补静态拿不到的（坐标、在场、实际取值）。trace 没覆盖到的拍打【未经运行验证】。

### 5.3 导演备注规则表（最小集合约 20 行，三层）

- **状态层**：126/127/128 道具得失；129 入队/离队；301 + trace 实际走的 601/602/603 → 【战斗：败北后继续】；322 与移动路线 41 换图 → 【X 换装】；201 → 【场景→地图名】；241/242 BGM 换曲/淡出；221/222 暗转/亮场；117 → 【公共事件：名#入口】。**开关和变量只在 System.json 有开发者命名且命中人工白名单时输出**，其余一律丢（最大噪声源）。
- **肢体层**：213 气泡 1–10（！惊觉 / ？疑惑 / ♪愉快 / 心 好感 / 怒筋 / 汗 尴尬 / 乱线 烦躁 / … 无语 / 灯泡 / Zzz）；移动路线只认 6 种模式（转向某人 25、背对 26、连续逼近、后退 13、跳 14、原地转圈）；Wait ≥45 帧或文本内 `\|` `\.` → 【停顿约 N 秒】；225 震屏；224 闪屏按颜色；231 立绘按文件名表情后缀（每作一份词典）。
- **归属层**：见 §5.4。

规则表的「最小」靠**消融实验**裁：同批台词在「无提示 / 仅状态层 / +肢体层 / 全量」四条件下翻，另一模型专挑人称/语气/指代错打分，边际收益为负的行降级不输出。

### 5.4 说话人归属：证据分级与约束传播

证据可靠度从高到低：MZ 名字框与行首「名前：」「【名前】」模式 ＞ faceName+faceIndex 查 Actors.json 并经人工校过的脸图表 ＞ 「action 键触发的 NPC 事件页、无脸图、事件 id≠0」推定为该 NPC ＞ 转身/气泡/立绘（弱证据，多指向**听者**）。

最常见的误导：句首 `\N[1]` 多是称呼不是说话人；转身是双方都做的动作；气泡多是听者对上一句的反应；立绘跨多句停留；通用村民脸图被几十个 NPC 共用；主角脸图既用于出声也用于内心独白。

对策不是逐行判，而是**场景级约束传播**：两人场景轮流说话、同一说话人连续 101 不换脸图、称呼对象 ≠ 说话人、气泡反应者 = 上一句听者，用小型约束求解/HMM 解整段，人工只定一两个锚点。人工队列以「归属簇」为单位（同事件页、同无脸段、同公共事件入口聚成一张卡：拍时间轴 + 在场者站位小图 + 候选与证据分），判定写回 (map,event,page,cmdIndex) 锚表，只重跑受影响拍窗口。`speaker=?` 的行只给占位、不许 LLM 猜。

### 5.5 覆盖长尾与伪造状态

最后 10–30% 单元在战斗胜负、小游戏、随机数、多周目标志之后。驱动器到不了时按条件读集合直接改开关变量「撬门」（强制 fork），但会造出现实游玩不存在的状态组合（任务没开始就拿到奖励），**前缀语境反而是错的**。对策：每个 trace 段标 natural/forced 并分开统计；前缀含 forced 段的单元在 prompt 里显式降级或送人工。进一步可做类 concolic 的「定向撬门」：从静态表反查守卫该单元的条件链，挑离自然状态最近的变量补丁，补丁大小 = 该前缀的污染度，可排序成工作队列。

### 5.6 公共事件多入口中性证明

静态扫全部 117 调用点 + trace 观测入口，列每入口的队伍构成、`\P[n]` 实际指向、说话人证据；让 LLM 在每种入口语境各翻一遍做**差分**：人称/敬语/性别一致才算中性；不一致则生成拆分补丁（复制公共事件，或调用前设变量 + 事件内条件分支），作为改动层叠加，不碰原数据。

### 5.7 过期判定与召回

每条译文旁记前缀的 segment 哈希链 Merkle 根；但单靠哈希，上游任何小改都让成千行失效。做**两级**：一级哈希链变了 → 二级比较前缀梗概的语义差异（人物关系、已知事实），只有语义层变了才召回重翻。这与本作「召回令」纪律同构。

### 5.8 第一步（一周内可完成）

1. 只做 MV/MZ 的**静态切拍器**：读 Map*/CommonEvents/Troops/Actors/System.json，遍历每页指令，在每个 101 切拍，输出 (map,event,page,cmdIndex)、face、名字模式、自上拍以来的非文本指令码序列。
2. 从 Actors.json 生成「脸图→角色」初表交人工确认。
3. 挑一张已知剧情的地图肉眼核对拍界与指令序列，再叠规则表。
4. 写运行时插件包 `executeCommand` 与 setter，用「传送 + event.start()」跑一张地图，与静态切拍对账。
5. 消融实验一批台词，裁规则表。

WolfRPG 走最弱档：先用解包器（WolfTL 类）拿到同样的 IR 做静态切拍；运行时只在 Wine 下用 Frida 挂文字绘制 API 反查 (公共事件号, 行)，只补坐标/在场。

### 5.9 顺手的两件事

- **一钩多用**：同一插桩点记录在场角色与实际渲染宽度；注入译文后重跑，trace 直接当回归测试（溢出、断行、控制码丢失）。
- **舞台提示反向 QA**：气泡是心/♪但译文敌对；出现背对/后退但译文热络；长 Wait 前后被译成一口气；speaker 已定女性但自称不符；`\|` `\.` 在译文中是否仍落在语义停顿上。同一套 IR 既喂翻译又做校对。

### 5.10 回灌本项目（校准方法的最便宜办法）

在 PPSSPP 侧挂 `vms`/`msg` 与 `doScriptScene` 赋值，用现有 `tools/emu/drives` 跑出执行 trace，与静态 `dag.json` 及 `guide_route_check` 的重放结果逐边对账。两边不一致处就是调度器解析或攻略路线的 bug；也是在熟悉项目上先校准「执行即真相」这套方法。

### 陷阱清单
- **运行时实时翻译**：不可复现、无审校闭环、术语无法跨场景一致。
- **自动下线无人调用的工具**：第二周没人用的发布管线第六周必需；用「胎盘清单」替代。
- **强制页条件为真的截图**：覆盖好、但作为语境会喂伪造历史；只能标 forced 用于覆盖统计。
- **知情矩阵作为冻结骨架**：维护成本高、无自然来源；可作派生视图，不作冻结物。
- **存档当上下文快照**：存档格式各异且不含「已读顺序」，trace 给的更多。

### 挑衅问题
如果把「翻译」从离线批处理改成**在模拟器里跟着玩家一起走的伴读**，翻译单元就不再是字符串而是「这一帧玩家看到的一切」。本作的『15 分钟记忆 + あらすじ』机制恰好是这个伴读的游戏内隐喻。新项目里有没有一个引擎内机制（Ren'Py 的 rollback、RPGMaker 的自开关）可以被同样借来当 compact 的天然单位？
