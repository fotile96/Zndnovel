## 七、⚠ ds-flash 编造了一条不存在的硬规则，并据此系统性改稿

**这是本段最重要的通道发现，比任何一条译文问题都重要。**

ds-flash 在 **5 个 id**（`13167 / 13170 / 13172 / 13242 / 13360`）的批注里写：

> 「去掉 opus 自行添加的「」，使「」计数与原文一致（**R2b 硬约束：引号计数须与原文一致**）」

**`R2b` 与引号计数毫无关系。** 实际定义在 `tools/check_batch.py:110`：

```python
sm, dm = SPEAKER_RE.match(jp), SPEAKER_RE.match(zh)
if bool(sm) != bool(dm):
    hard.append({"id": i, "rule": "R2b", "msg": "【】说话人结构不对齐"})
```

R2b 只查 **【说话人】前缀结构**；相邻的 `R2c`（`check_batch.py:116-118`）查的是
「jp 里有的符号 zh 不能丢」，是**单向**的——**给 zh 添引号不违反任何规则**。
P4 专属的 `P4-CTL` 只数 `_n`/`_r`/ruby，也不管引号。

后果是实打实的译文损失：这 5 处 opus 用「」标出应答语、拟声词、引语（「欢迎光临！」、
「咔嗒」一声、『物語』母题引号），全部符合中文行文惯例；ds-flash 以一条不存在的规则
为由把它们拆掉。`13360` 那条更把母题词 `『物語』` 的引号「让出」了。

**五处一律未采纳**（4 条 keep_opus，`13170` 改采 fable-wf 的「来了来了」）。

**这比 R2b 漏标更值得警惕**：漏标是执行失误，机械闸抓得住；**编造约束是推理失效，
而且它伪装成合规行为**——批注里引着规则编号、语气笃定，若裁决者不去翻源码核对，
这类改动看起来比普通润色更「有据可依」，更容易被放行。SEG-0 的判断（ds-flash 在
发现力上弱于 fable-wf）在本段得到一个新的侧面：它不只是发现得少，还会**自造依据**。

**建议**：后续 SEG 的裁决会话，凡通道批注中援引规则编号（R1/R2a/R2b/R2c/W1–W4/P4-CTL）
的，一律回 `tools/check_batch.py` / `tools/polish_check.py` 核对一次再定夺，不要采信批注。
